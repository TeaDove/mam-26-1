## Слайд 4. Память — шкаф с ячейками

- Память = огромное число пронумерованных ячеек; номер называется адресом.
- Чтобы хранить 5 чисел «подряд», нужно 5 свободных ячеек подряд.

~~~text
Адрес:      a      a+4      a+8     a+12     a+16     a+20     a+24     a+28
Ячейки: [      ] [      ] [      ] [      ] [      ] [      ] [      ] [      ]
~~~

## Слайд 5. Массив: непрерывный блок

~~~python
A = [10, 20, 30, 40, 50]
A[2]
~~~

Результат: 30, мгновенно.

- Все элементы лежат подряд, в одном непрерывном блоке.
- Адрес элемента вычисляется: адрес_начала + i × размер_элемента.
- Чтение по индексу: O(1) — это называется произвольный доступ.

Вопрос: что нужно сделать, чтобы вставить элемент в середину?

Все, кто справа, должны сдвинуться → O(n).

Аналогия: в кинозале нет 6 свободных мест подряд — компании придётся пересаживаться.

## Слайд 6. Связанный список

- Элементы разбросаны в памяти где угодно.
- Каждый узел хранит: значение + адрес следующего узла.

~~~python
class Node:
    def __init__(self, value, next=None):
        self.value = value
        self.next = next
~~~

Аналогия: охота за кладом — каждая подсказка ведёт к следующей.

Массив: непрерывный блок — адрес вычисляется.

| Индекс | 0 | 1 | 2 | 3 | 4 |
| --- | --- | --- | --- | --- | --- |
| Значение | 10 | 20 | 30 | 40 | 50 |

Связанный список: узлы разбросаны, каждый знает адрес следующего.

~~~text
10 → 20 → 30 → 40 → 50 → None
~~~

## Слайд 7. Компромиссы

| Операция | Массив | Связанный список |
| --- | --- | --- |
| Чтение i-го элемента | O(1) | O(n) |
| Вставка в известное место | O(n) | O(1) |
| Удаление известного места | O(n) | O(1) |
| Тип доступа | Произвольный | Последовательный |

«Известное место» = если адрес узла уже у нас есть, например, мы только что до него дошли.

«Лучшей» структуры не бывает — бывает подходящая под набор операций.

## Слайд 8. Динамический массив

## Слайд 9. Проблема: массив заполнен

- Массив занимает непрерывный блок — расти на месте нельзя: соседние ячейки заняты.
- Единственный выход: переезд — новый блок побольше, скопировать всё.

Вопрос: но list.append в Python работает мгновенно, даже на миллионах элементов. Как так?

## Слайд 10. Идея: удвоение

- Заполнился → новый массив вдвое больше → копируем → продолжаем работать.
- После переезда на 2n элементов следующие n вставок — копейки.

График «Динамический массив: дорогие вставки редки»: высокие затраты на переезд при вставках 2, 3, 5 и 9;
остальные вставки дешёвые. Линия показывает среднюю стоимость вставки, оси — номер вставки и стоимость операции.

В среднем одна вставка стоит O(1) — говорят: амортизированная стоимость O(1).

## Слайд 11. Почему не расширять на +1?

Вопрос: кажется, что +1 экономнее — не будет «пустых» ячеек. В чём ошибка рассуждения?

Каждая вставка = копирование всех элементов → каждая вставка O(n).

При удвоении: на n вставок суммарно ≈ 2n копирований.

~~~python
n = 1000
capacity, size, total_copies = 1, 0, 0
for _ in range(n):
    if size == capacity:
        total_copies += capacity
        capacity *= 2
    size += 1
print(f"вставок: {n}, скопировано элементов при переездах: {total_copies}")
print(f"в среднем на вставку: {total_copies / n:.1f} копирований")
~~~

При переезде копируем все элементы.

~~~text
вставок: 1000, скопировано элементов при переездах: 1023
в среднем на вставку: 1.0 копирований
~~~

## Слайд 12. Стек и очередь

## Слайд 13. Структура = набор операций

Структура данных характеризуется операциями, которые она поддерживает.

Стек — как стопка тарелок:

- push — положить сверху;
- pop — снять сверху;
- принцип LIFO: last in — first out.

Где встречается: undo в редакторе, кнопка «назад» в браузере, стек вызовов (лекция про рекурсию).

## Слайд 14. Очередь

Очередь — как очередь в магазине:

- enqueue — встать в хвост;
- dequeue — обслужить того, кто первый;
- принцип FIFO: first in — first out.

Где встречается: очередь задач, буфер принтера, обработка событий.

## Слайд 15. Хеш-таблицы

## Слайд 16. Обещание лекции 1

Как получить O(1) для поиска без сортировки?

- Кассир ищет цену авокадо в книге цен: постранично — O(n), бинарно — O(log n).
- «Помощница Мэгги» помнит все цены наизусть — отвечает мгновенно.
- Хеш-таблица — способ дать компьютеру память Мэгги.

## Слайд 17. Хеш-функция

Хеш-функция — функция, отображающая ключ (строку) в индекс массива.

~~~python
def h(key, size=10):
    return sum(ord(ch) for ch in key) % size
~~~

Требования к хеш-функции:

- один и тот же ключ → всегда тот же индекс;
- разные ключи → разные индексы (в идеале);
- индекс не выходит за границы таблицы.

## Слайд 18. Хеш-таблица = хеш-функция + массив

~~~python
phone_book = {}
phone_book["[REDACTED NAME]"] = "[REDACTED PHONE NUMBER]"
phone_book["[REDACTED NAME]"]
~~~

Получаем сохранённый номер мгновенно.

- Вставка, поиск и удаление по ключу: O(1) в среднем.
- В Python это dict — одна из самых используемых структур языка.

## Слайд 19. Коллизии

Вопрос: что если два разных ключа попадут в один индекс?

Это коллизия — и она неизбежна: ключей больше, чем ячеек.

Решение — цепочки: в ячейке живёт связанный список.

Вот где пригодился связанный список из части 1!

~~~python
size = 7
table = [[] for _ in range(size)]

def h(key):
    return sum(ord(ch) for ch in key) % size

for w in ["апельсин", "молоко", "авокадо", "хлеб", "сыр", "кефир"]:
    table[h(w)].append(w)

for i, chain in enumerate(table):
    print(f"ячейка {i}: {chain}")
~~~

~~~text
ячейка 0: ['апельсин', 'хлеб', 'сыр']
ячейка 1: ['кефир']
ячейка 2: ['авокадо']
ячейка 3: []
ячейка 4: ['молоко']
ячейка 5: []
ячейка 6: []
~~~

## Слайд 20. Коэффициент заполнения

Коэффициент заполнения = число элементов / число ячеек.

- Заполнение > 0.7 → цепочки длинные → работа замедляется.
- Решение: resize — переезд в таблицу вдвое больше.
- Вот где пригодился динамический массив из части 2!
- Хорошая хеш-функция = равномерное распределение по ячейкам.

Вопрос: почему в худшем случае поиск всё-таки O(n)?

Все ключи в одной ячейке → поиск по цепочке — линейный поиск.

## Слайд 21. А теперь — по-настоящему

Замерим поиск по 1 000 000 записей.

~~~python
import time

n = 1_000_000
data_list = [f"ключ_{i}" for i in range(n)]
data_dict = {f"ключ_{i}": i for i in range(n)}
probe = "ключ_999999"

t0 = time.perf_counter()
found = probe in data_list
t_list = time.perf_counter() - t0

t0 = time.perf_counter()
found = probe in data_dict
t_dict = time.perf_counter() - t0

print(f"список:  {t_list*1000:.1f} мс")
print(f"словарь: {t_dict*1000:.4f} мс")
print(f"разница: {t_list/t_dict:,.0f} раз")
~~~

Для списка выбран худший случай: последний элемент. В списке выполняется линейный поиск, в словаре — поиск
по хеш-таблице.

Вывод на слайде:

~~~text
список:  42.5 мс
словарь: 0.1151 мс
разница: 369 раз
~~~

## Слайд 24. Какую структуру когда выбирать

| Структура | Сильная сторона | Слабая сторона |
| --- | --- | --- |
| Массив | Чтение по индексу O(1) | Вставки/удаления O(n) |
| Связанный список | Вставки/удаления O(1) | Чтение i-го элемента O(n) |
| Стек / очередь | Простой порядок обработки | Доступ только к концам |
| Хеш-таблица | Поиск/вставка/удаление O(1) в среднем | Нет порядка, худший случай O(n) |

## Слайд 25. Три мысли лекции

1. «Лучшей» структуры не бывает — выбираем подходящую под набор операций.
2. Динамический массив: удвоение делает переезды редкими → вставка O(1) в среднем.
3. Хеш-таблица: O(1) в среднем — платим коллизиями и отсутствием порядка.
