# Лабораторная 1 — графы знаний: MinerU + GraphRAG

Два учебных текста по контролируемой прокатке стали были распознаны с помощью MinerU и
вместе превращены в **один общий граф знаний** с помощью GraphRAG:

- `tanaka1981` — T. Tanaka, *Controlled rolling of steel plate and strip* (английский, 28 страниц);
- `stat3` — статья о выборе схемы контролируемой прокатки листов с ускоренным охлаждением
  (русский, 10 страниц).

Ссылки на исходные PDF и их контрольные суммы — в `SOURCES.md`. Сами PDF в репозиторий не
включены.

## Структура папки

| Путь | Описание |
| --- | --- |
| `sources/tanaka1981.md`, `sources/stat3.md` | Markdown-результат распознавания PDF в MinerU — вход GraphRAG |
| `graph/` | Общий граф по обоим текстам и все артефакты к нему (см. ниже) |

## Пайплайн

1. **Распознавание — MinerU 4.0.5.** Каждый PDF преобразован в Markdown
   (`sources/tanaka1981.md`, `sources/stat3.md`) с распознаванием структуры страницы, формул и
   таблиц.
2. **Индексация — GraphRAG 3.1.2.** Оба Markdown-файла лежат в одной входной папке одного
   проекта GraphRAG и индексируются за один запуск в один граф. Модель для извлечения
   сущностей, связей и описаний сообществ — `gpt-4o-mini`; векторные представления текста —
   `bge-m3`. Текст режется на чанки по 1200 токенов с перекрытием 100, из каждого чанка
   извлекаются сущности и связи, одноимённые сущности из разных чанков (и из разных книг)
   сливаются в одну вершину, затем граф кластеризуется на сообщества (Leiden) и для каждого
   сообщества генерируется отчёт.
3. **Кластеризация всего графа.** По умолчанию GraphRAG кластеризует только наибольшую
   компоненту связности (`cluster_graph.use_lcc: true`). В общем графе это английская часть,
   и русский текст остался бы совсем без сообществ и отчётов, поэтому в `settings.yaml`
   выставлено `use_lcc: false` — на сообщества разбит весь граф.
4. **Визуализация.** Граф отрисован в интерактивный `graph.html` (pyvis: физика включена,
   размер узла пропорционален степени, цвет — книга-источник, при наведении — тип, источник
   и описание сущности) и в статичный `graph.png` (matplotlib, spring layout, подписаны 25
   узлов с наибольшей степенью, синий — `tanaka1981`, красный — `stat3`).

### Типы сущностей

Использован один набор типов, подобранный под металлургию:

`material`, `steel grade`, `alloying element`, `process`, `process parameter`,
`mechanical property`, `microstructure`, `phase`, `equipment`, `phenomenon`, `person`,
`organization`.

### Слились ли английская и русская части

**Нет.** Граф формально один, но фактически состоит из двух не связанных между собой частей:

- ни одна сущность не извлечена из обеих книг одновременно, рёбер между сущностями
  `tanaka1981` и `stat3` — 0;
- из 28 компонент связности 13 целиком английские и 15 целиком русские; наибольшая
  компонента (217 узлов) — полностью `tanaka1981`, наибольшая русская — 47 узлов вокруг `КП`.

Причина — GraphRAG сливает сущности только по точному совпадению названия, а
`gpt-4o-mini` называет сущности на языке исходного текста: `CONTROLLED ROLLING` и `КП` /
`КОНТРОЛИРОВАННАЯ ПРОКАТКА`, `AUSTENITE` и `АУСТЕНИТ` остаются разными вершинами. Связать
части могли бы нормализация терминов (перевод и приведение к единому словарю, раскрытие
сокращений вроде `КП`) — это задача предобработки в lab-2.

Полные цифры, распределение узлов и рёбер по типам сущностей, размеры компонент и топ-15
сущностей по степени — в `graph/stats.md`.

## Содержимое папки `graph/`

| Файл | Описание |
| --- | --- |
| `graph.graphml` | Граф сущностей и связей, построенный GraphRAG; у вершин атрибуты `type`, `description`, `source`, `frequency`, `degree`, `community_level0`, у рёбер — `weight`, `description` |
| `graph.html` | Интерактивная визуализация (pyvis) |
| `graph.png` | Статичная картинка графа |
| `stats.md` | Количественные показатели, структура графа, распределения по типам и топ-15 сущностей по степени |
| `entities.csv` | Сущности (название, тип, степень, частота, описание) |
| `relationships.csv` | Связи (источник, цель, вес, описание) |
| `settings.yaml` | Конфигурация GraphRAG, с которой выполнялся запуск (ключ API и адреса моделей — плейсхолдеры) |
