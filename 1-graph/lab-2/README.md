# Лабораторная 2 — предобработка текста и сравнение графов знаний

Задание — в [TASK.md](TASK.md), конспект лекции — в [predobrabotka.md](predobrabotka.md).

Два учебника по контролируемой прокатке стали — `tanaka1981` (английский обзор, 28 страниц) и `stat3`
(русская статья, 10 страниц) — вместе образуют один общий граф. Сравниваются два графа:

- **грязный** — GraphRAG по markdown MinerU как есть, граф из [../lab-1](../lab-1);
- **чистый** — GraphRAG по тому же markdown после полной предобработки.

Настройки GraphRAG у обоих графов одинаковые: gpt-4o-mini, эмбеддинги bge-m3, те же промпты и типы
сущностей, чанк 1200 токенов, кластеризация без ограничения на крупнейшую компоненту. Отличается только
предобработка текста.

Презентация — [results/presentation.pptx](results/presentation.pptx).

## Пайплайн

```
грязный:  PDF → MinerU → GraphRAG
чистый:   PDF → MinerU → chunking → очистка → нормализация → токенизация → векторизация → GraphRAG
```

После каждого этапа считаются метрики — по каждой книге и суммарно. Каждый этап проверял независимый
ревьюер. Найденные критичные ошибки исправлены, метрики пересчитаны.

| Этап | Что делается | Метрики |
| --- | --- | --- |
| 1. Chunking | Разбиение по разделам и абзацам, до ~1000 токенов; не режет формулы и таблицы, режет на конце предложения. Каждый чанк — отдельный документ GraphRAG, поэтому GraphRAG его не перерезает. Чанки сохранены для RAG. | [01_chunking.md](results/metrics/01_chunking.md) |
| 2. Очистка | Колонтитулы, номера страниц, ссылки на картинки, HTML-сноски, маркеры цитат, список литературы, метаданные авторов (PII); склейка абзацев, разорванных страницами и подписями; переносы; проверенные исправления OCR; шум в LaTeX. Все правки — в журнале `data/02_clean_audit.jsonl`. | [02_cleaning.md](results/metrics/02_cleaning.md) |
| 3. Нормализация | Единицы (`730<sup>0</sup>С` → `730 °C`, диапазоны через тире, Н/мм²), LaTeX-величины из OCR в текст, Ar3/Ac3, греческие обозначения фаз, аббревиатуры, двуязычный глоссарий терминов. Формулы и таблицы защищены маской. Журнал — `data/03_normalized_audit.jsonl`. | [03_normalization.md](results/metrics/03_normalization.md) |
| 4. Токенизация | Словная токенизация с формулами как единым токеном; OOV по wordfreq и доменному глоссарию; подсловные токенизаторы o200k (gpt-4o-mini) и bge-m3. | [04_tokenization.md](results/metrics/04_tokenization.md) |
| 5. Векторизация | bge-m3 (1024) для каждого чанка — задел для RAG; TF-IDF на окнах по 300 слов; межъязыковое сходство. Векторы вершин записаны атрибутом `embedding` в графы. | [05_vectorization.md](results/metrics/05_vectorization.md) |

### Ключевая находка нормализации

В грязном графе английская и русская части не связаны: GraphRAG склеивает сущности только по точному
названию, а модель называет сущности на языке текста (`CONTROLLED ROLLING` и `КП`). Глоссарий с английским
термином в скобках после русского (`аустенита (austenite)`) не помогает: проверено вызовом промпта
GraphRAG, модель всё равно называет сущность `АУСТЕНИТ`. Работает только вариант, где канонический
английский термин стоит первым — один раз на чанк: `controlled rolling (КП, контролируемая прокатка)`,
`austenite (аустенита)`. Остальные упоминания остаются русскими.

Оговорки, отмеченные ревьюерами:

- OOV у tanaka снизился в основном из-за удаления списка литературы, у stat3 — из-за склеенных переносов.
  После нормализации OOV считается по исходным словам: вставленные глоссарием слова в знаменатель не входят.
- Около 40% роста межъязыкового сходства дают сами вставленные английские термины.
- 274 LaTeX-обозначения (`$\gamma$`, `$850 ^ { 0 } \mathbf { C }$`, `$Ar_{3}$`) после нормализации — обычный
  текст, поэтому число «формул» в столбце после нормализации меньше. Это преобразование, а не потеря.
- Разреженность TF-IDF сравнивается на одинаковых окнах по 300 слов, а не на чанках разного размера.

### LLM-as-a-judge (gpt-4.1)

Судья оценивал каждый текстовый фрагмент вместе с извлечёнными из него сущностями и связями, размечал все
вершины (основная / второстепенная / шум) и подтверждал кандидатов в дубликаты, найденных по близости
эмбеддингов названий. Ответы судьи — `results/metrics/07_judge_units_*.json`.

Шум грязного графа: транслит (`KONTROLIROVANNOY PROKATKI`, `NEPRYEVNOLITOGO METALLA`), переносы в

(`SEPARATION = SEPARATIONS`), их убрала бы лемматизация сущностей.

## Выводы

- Структурный chunking почти перестал рвать предложения и не режет формулы и таблицы.
- Очистка убрала почти весь шум и сохранила все числа, формулы и ячейки таблиц содержательной части.
- Нормализация терминов по схеме «английский канон первым» связала английскую и русскую части графа.
- Чистый граф связнее: компонент меньше, циклов больше, все пары концептов достижимы, шума меньше.
- Не решено: дубликаты «ед. / мн. число». Ограничения: глоссарий ручной, один прогон GraphRAG, один судья.

## Запуск

Нужны Python 3.14 и `uv`. Эмбеддинги — локальный сервер bge-m3 с OpenAI-совместимым API
(`LAB2_EMBEDDING_URL`), LLM — OpenAI-совместимый API (`LAB2_OPENAI_BASE_URL`, ключ — `LAB2_OPENAI_API_KEY`
или stdin). Грязный граф берётся из выхода GraphRAG lab-1 (`LAB2_DIRTY_GRAPHRAG_DIR`).

```bash
uv sync
uv run lab2 chunk       # 1. chunking
uv run lab2 clean       # 2. очистка
uv run lab2 normalize   # 3. нормализация
uv run lab2 tokenize    # 4. токенизация
uv run lab2 vectorize   # 5. векторизация
uv run lab2 export      # чанки → graphrag-clean/input
scripts/run_index_clean.sh < api_key   # GraphRAG для чистого графа
uv run lab2 compare     # сравнение графов и LLM-as-a-judge
uv run lab2 figures     # картинки графов
uv run --with pyvis python scripts/build_html_graphs.py   # интерактивные HTML-графы
uv run python scripts/build_presentation.py
uv run pytest && uv run ruff check . && uv run ruff format --check .
```
