# Задание 2 — работа над ошибками

План доработки лабораторной по замечаниям преподавателя с защиты 30.09.
Исходное задание — [TASK.md](TASK.md), текущее решение — [README.md](README.md).

## Главное замечание

Все критерии сравнения считаются **по графам, обходами графа**, а не по тексту.
Для вершины обходом в ширину на 2–3 уровня (окно «2 в глубину × 3 в ширину») собирается контекст:
соседние вершины, рёбра и их описания. Дальше критерий считается алгоритмом, а если без модели
не обойтись — контекст отдаётся LLM. Несколько критериев считаются за один обход.

## Принятые решения

| Вопрос | Решение |
| --- | --- |
| Порядок этапов | очистка → нормализация → **chunking** → токенизация → векторизация |
| Экстрактор графа | gpt-4o-mini, как в lab-1 — графы остаются сравнимыми со старыми |
| Судья | gpt-4.1, только там, где без LLM нельзя (непротиворечивость) |
| Настройки GraphRAG | прежние: bge-m3, окна 1200/100 токенов, те же промпты и типы сущностей; чистые чанки (≤ 1100 токенов) GraphRAG не перерезает |
| Бюджет OpenAI | ≈ $1–2 на оба графа и судью |

## 1. Предобработка

- [x] **Новый порядок этапов.** Очистка и нормализация работают с книгой целиком, chunking режет уже чистый текст.
- [x] **Канонический английский термин** ставится первым не «раз на чанк», а заново, если с прошлой пометки прошло ≥
  3000 символов — так пометка не зависит от будущего разбиения.
- [x] **Лемматизация.**
  - русский (pymorphy3): существительные и пары «прилагательное + существительное», стоящие подряд, без окна →
    именительный падеж, единственное число;
  - английский: существительные во множественном числе → единственное;
  - для сравнения считается доля слов, которую изменила бы полная лемматизация.
- [x] **Оценка этапов по смыслу, а не количеством** — на эталонных страницах:
  - эталон: по 2 страницы из каждой книги, выверенный вручную по PDF;
  - **очистка:** точность, полнота и F1 удалений («удалено 94% того, что должно было уйти, лишнего — 1%»), CER и WER
    сырого и чистого текста относительно эталона;
  - **нормализация:** доля верно приведённых единиц и терминов, доля слов, изменённых лемматизацией;
  - **chunking:** доля разорванных предложений, формул и таблиц;
  - **токенизация:** OOV-rate, целостность формул;
  - **векторизация:** размер словаря и разреженность TF-IDF; **Hit Rate@k, MRR, NDCG@10** на 25–30 вопросах (оба языка)
    для грязных и чистых чанков.
- [x] У каждой метрики — пояснение: почему значение выросло или упало и хорошо ли это.

Итог этапа: [results/preprocessing_report.md](results/preprocessing_report.md), метрики — `results/metrics/0*`, эталон —
`data/gold/`.

## 2. Графы

- [x] **Грязный граф:** сырой markdown MinerU **без списка литературы**, больше ничего не меняем.
- [x] **Чистый граф:** текст после нового пайплайна.
- [x] Оба графа — GraphRAG с одинаковыми настройками.
- [x] Векторы bge-m3 — атрибутом каждой вершины.

Итог этапа: графы с векторами — `results/graphs/*_graph_with_vectors.graphml.gz`, выход GraphRAG —
`graphrag-dirty/output` и `graphrag-clean/output`, сводка — `results/metrics/07_graphs.json` (грязный: 324 вершины, 336
рёбер; чистый: 424 вершины, 437 рёбер; у всех вершин
вектор bge-m3 размерности 1024). Встречные связи A→B и B→A объединяются в одно ребро с обоими описаниями
(9 в грязном графе, 13 в чистом).

Оговорка: настройки GraphRAG одинаковые, но входы разбиты по-разному. Грязный текст GraphRAG режет окнами
1200/100 (28 фрагментов, в среднем 1137 токенов), чистый приходит структурными чанками (36 фрагментов,
в среднем 692 токена) — это этап предобработки. Мелкие фрагменты дают модели больше вызовов на токен текста:
17,0 вершины на 1000 токенов против 10,2. Поэтому часть прироста вершин и рёбер — эффект chunking, а не очистки;
вклад chunking отдельно измерен на поиске (2×2 в этапе 1). В этапе 3 счётные показатели дополнительно
приводятся на 1000 входных токенов.

## 3. Критерии сравнения — обходами графа

| Критерий | Как считаем | LLM |
| --- | --- | :---: |
| **Полнота по тексту** | Термины текста (глоссарий + лемматизированные именные группы): какая доля найдена среди вершин — по совпадению лемм и по близости эмбеддингов | нет |
| **Непротиворечивость** | Для вершины — контекст BFS-2 (соседи, описания рёбер) и исходный фрагмент текста → судья: определён ли термин полностью, есть ли противоречия. Выборка — 120 вершин на граф | да |
| **Корреференции** | Дубликаты по совпадению лемм и эмбеддингам названий. BFS-3: вершины-местоимения (он, его, она, это…) удаляются, их подграф поднимается на уровень выше, число операций считается | нет |
| **Шум** | 5 регулярных правил по всем вершинам: только знаки и скобки; переменные формул («A2», одиночные буквы); числа и единицы («°C»); местоимения и служебные слова; обрывки и склейки слов, транслит; шестая проверка — слова нет ни в тексте, ни в частотном словаре. Доля по каждому правилу, сверка с числом вершин | нет |
| **Целостность формул и таблиц** | Каждая формула и таблица исходного текста: лежит целиком в одной вершине, в окне обхода «2 × 3» или разорвана | нет |
| **Показатели графа** | Компоненты связности, мосты, точки сочленения, степени, циклы | нет |
| **Покрытие ПрО** | 40 ключевых понятий: по названиям и через векторы вершин | нет |
| **Вершины и рёбра по типам** | Все типы вершин, рёбра — по парам типов | нет |

Итог этапа: [results/graph_criteria_report.md](results/graph_criteria_report.md), данные —
`results/metrics/08_graph_comparison.json`, ответы судьи — `results/metrics/08_consistency_{dirty,clean}.json`.
