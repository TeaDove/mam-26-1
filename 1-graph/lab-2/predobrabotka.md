# Предобработка

Конспект лекционной презентации «Предобработка» (курс по графам).

## Схема предобработки

1. **Извлечение данных** ← PDF, Web, DOCX/PPTX/XLSX
2. **Разбиение на блоки** ← chunking с защитой формул
3. **Очистка** ← шум, OCR-артефакты, PII
4. **Нормализация** ← лемматизация, единицы, даты
5. **Токенизация** ← словесная, субсловная, LaTeX-aware
6. **Аугментация** ← синонимы, БЯМ, числовые параметры
7. **Векторизация** ← TF-IDF, SBERT, E5, AST-формулы
8. **Оценка качества** ← CER, WER, Hit Rate, MRR

## Извлечение из PDF

Цель: преобразовать PDF в машиночитаемый текст с сохранением:

- порядка чтения;
- иерархии документа;
- таблиц (включая объединённые ячейки);
- математических формул → LaTeX;
- химических уравнений → LaTeX;
- физических размерностей;
- метаданных (автор, дата, версия).

### Стратегии извлечения из PDF

Три типа PDF и три стратегии:

| Тип PDF | Стратегия | Инструменты |
| --- | --- | --- |
| Цифровой (текстовый слой) | Прямое извлечение | PyMuPDF, pdfplumber |
| Скан (изображение) | OCR | Tesseract, ABBYY FineReader, Google Vision |
| Гибридный | PyMuPDF + выборочный OCR | Комбинация |

### Специализированные задачи

- **Математические формулы**: Mathpix API, LaTeX-OCR (pix2tex), MathGPT
- **Химические формулы**: ChemDataExtractor, RDKit, OPSIN
- **Физические размерности**: Pint, quantities
- **Layout-анализ**: Detectron2, LayoutLMv3, YOLO
- **Универсальные парсеры**: MegaParse, PyMuPDF4LLM

### Алгоритм парсинга PDF

1. Получение PDF.
2. Проверка формата и целостности.
3. Определение типа: цифровой / скан / гибрид / форма.
4. Выбор стратегии извлечения (PyMuPDF / Tesseract / гибрид).
5. Извлечение структуры (layout-анализ).
6. Извлечение метаданных (номер, дата, автор, версия).
7. Обнаружение технических параметров:
   - числа, единицы измерения (нормализация через Pint);
   - химические формулы;
   - математические формулы.
8. Валидация через сверку с эталонными шаблонами (ГОСТ, ISO, ТУ).
9. Обогащение для RAG-систем.
10. Сохранение в корпоративное хранилище и векторные БД.
11. Логирование: время, статус, ошибки.
12. Отправка уведомления в систему мониторинга.

## Web-скрапинг

Цель: автоматический сбор данных с сайтов поставщиков, порталов, торговых площадок.

**Что собираем:**

- цены на сырьё и оборудование;
- технические характеристики;
- нормативную документацию;
- данные о конкурентах.

**Проблемы:**

- 40 % сайтов — антибот-защита Cloudflare/Akamai;
- 30 % — динамические SPA-приложения;
- научно-технические страницы: MathML, MathJax, SMILES, InChI.

**Требования к точности:** цены → > 95 %; технические параметры → > 90 %.

### Алгоритм Web-скрапинга

Загрузка URL → robots.txt → HTML → антибот-проверка → рендеринг SPA → извлечение цен → извлечение технических параметров → JSON-LD → нормализация валют → нормализация единиц → сохранение в БД → логирование → метрики в Prometheus.

### Инструменты по типу контента

| Тип контента | Инструменты |
| --- | --- |
| Статические страницы | Trafilatura, newspaper3k, Readability, boilerpy3 |
| Динамические SPA | Playwright, Puppeteer |
| Обход антибот | Ротация User-Agent, прокси-пулы, stealth-режимы, 2Captcha |
| LLM-экстракторы | LLMParser, Scrag, Crawl4ai, Firecrawl |
| Структурированные данные | JSON-LD, Microdata, RDFa (extruct) |
| Математика | MathJax API, Pandoc (MathML→LaTeX) |
| Химия | ChemDataExtractor, RDKit, OPSIN |

**Проблемы:**

- встроенные OLE-объекты (Excel внутри Word, диаграммы в PPTX);
- формулы Equation Editor (OMML);
- химические структуры ChemDraw;
- объединённые ячейки в Excel;
- заметки докладчика в PPTX.

**Инструменты:**

- DOCX: python-docx, docx2txt, lxml, LibreOffice

## Семантическое разбиение на блоки

Цель: адаптация под контекстное окно БЯМ + сохранение смысла.

**Требования:**

- размер блока: 512–1024 токена;
- перекрытие: 10–20 %;
- целостность формул, чисел с единицами, таблиц;
- сохранение смысловой целостности (не разрывать предложения и абзацы).

### Инструменты chunking

- **Базовые**: CharacterTextSplitter, RecursiveCharacterTextSplitter (LangChain)
- **Семантические**: SemanticChunker (LangChain), SentenceTransformers (spaCy)
- **Оптимизация размера**: tiktoken (OpenAI), AutoTokenizer (HF)
- **Иерархические**: MarkdownHeaderTextSplitter, HTMLHeaderTextSplitter
- **LaTeX-aware**: кастомные регулярные выражения + latex2text
- **LLM-управляемые**: GPT-4o, Claude-3.5-Sonnet

### Метрики chunking

- средний размер блока;
- стандартное отклонение размера (≤ 200 токенов);
- доля разорванных предложений (≤ 5 %);
- доля разорванных абзацев (≤ 2 %);
- процент разорванных формул (→ 0);
- Hit Rate при поиске (> 90 %).

## Очистка

Цель: удалить шум, восстановить целостность, сохранить смысловую корректность.

**Что считается шумом:**

- непечатные и управляющие символы (ASCII < 32, кроме `\n`, `\r`, `\t`);
- лишние пробелы и табуляции;
- HTML/XML-теги;
- стоп-слова (с осторожностью для технических текстов);
- персональные данные (GDPR, ФЗ-152);
- OCR-шум (ошибки распознавания);
- искажённые числовые параметры (потеря разделителей, «,» вместо «.»);
- повреждённые формулы;
- нарушенные структуры таблиц;
- служебные метки (номера страниц, колонтитулы);
- единицы измерения в разных системах.

### Эволюция методов очистки

| Период | Подход | Точность |
| --- | --- | --- |
| 1990–2000 | Правила, регулярные выражения (re, grep, sed) | ~ 60 % |
| 2005–2015 | Словарные методы (hunspell, pyspellchecker) | 70–75 % |
| 2015–2020 | CRF + NER (spaCy, DeepPavlov) | ~ 85 % |
| 2020–2023 | Трансформеры (BERT, RoBERTa), Presidio для PII | ~ 95 % |
| 2024–наст. | Гибрид: правила + NER + БЯМ + LLM-as-a-judge | > 95 % |
| Перспектива | Мультимодальная очистка (GPT-4o, Claude 3.5) | — |

### Алгоритм очистки

1. Предобработка:
   - извлечение таблиц (tabula-py, camelot);
   - изоляция формул маркерами `[MATH_0]`;
   - вынос служебных элементов в метаданные.
2. Базовая очистка: удаление управляющих символов, нормализация пробелов.
3. Удаление HTML/XML-тегов: BeautifulSoup.
4. Исправление OCR-артефактов: контекстная замена (0↔O, 1↔l), словарная коррекция.
5. Приведение к нижнему регистру с защитой аббревиатур через маркеры.
6. Удаление стоп-слов с проверкой, не является ли слово частью термина (POS-теггинг).
7. Фильтрация PII: регулярные выражения + NER + маскировка `[PII_NAME_1]`.
8. Очистка числовых параметров: нормализация разделителей, сохранение единиц.
9. Восстановление формул и таблиц из маркеров.
10. Валидация качества: CER, WER, сохранность чисел, формул, таблиц.

### Проблемы и решения при очистке

| Проблема | Решение |
| --- | --- |
| Регулярные выражения портят LaTeX | Временная замена формул маркерами + SymPy для валидации |
| Потеря структуры таблиц | Извлечение таблиц до очистки, очистка каждой ячейки отдельно |
| OCR-артефакты в числах | Контекстная коррекция + словари терминов + диапазонные значения |
| Потеря единиц измерения | Словари + Pint |
| Ложные срабатывания при фильтрации PII | Гибрид: правила → NER → словарь + мониторинг |
| Смешанные языки в документе | Определение языка до очистки, мультиязычные инструменты |
| Большие объёмы | Пакетная обработка, кеширование результатов |

Инструменты: `re`, `unicodedata`, nltk, spaCy, Presidio, scrubadub, tabula-py, camelot, SymPy.

## Нормализация

**Отличие от очистки:**

- очистка удаляет шум и восстанавливает целостность;
- нормализация приводит все данные к единому стандарту.

**Задачи нормализации:**

- лемматизация (понимание смысла);
- стемминг (скорость поиска);
- приведение регистра;
- нормализация дат → ISO 8601;
- нормализация единиц измерения → СИ;
- нормализация аббревиатур и терминов;
- нормализация числовых параметров;
- нормализация формул (канонический вид);
- нормализация таблиц;
- нормализация химических формул.

Цель: обеспечить корректное сравнение, поиск и анализ.

### Эволюция методов нормализации

| Период | Подход | Инструменты |
| --- | --- | --- |
| 1990–2000 | Словарные методы, стемминг | Snowball, Porter stemmer |
| 2005–2015 | Морфологические анализаторы | pymorphy2, Mystem |
| 2015–2020 | Контекстные методы | spaCy, Stanza |
| 2020–2023 | Трансформеры (точность 92–95 %) | BERT, RuBERT |
| 2024–наст. | Гибрид: морфология + контекст + БЯМ | pymorphy2 + BERT + GPT |
| Перспектива | Мультимодальная нормализация | GPT-4o, Claude 3.5 |

### Алгоритм нормализации

1. Предобработка: извлечение чисел, единиц, формул, таблиц.
2. Нормализация единиц измерения: приведение к СИ через Pint.
3. Нормализация дат: → ISO 8601 (2025-03-12) через dateutil.
4. Нормализация аббревиатур: словарь ПрО + NER + БЯМ для неоднозначностей.
5. Лемматизация или стемминг:
   - поиск → стемминг;
   - извлечение смысла → лемматизация;
   - технические тексты → словарь терминов.
6. Нормализация чисел: единый формат, научная нотация → десятичная.
7. Нормализация формул: LaTeX → канонический вид через SymPy, сохранение AST.
8. Нормализация таблиц: единая структура, типы данных через pandas.
9. Валидация: сохранность чисел, корректность единиц, формул, таблиц.

### Проблемы и решения при нормализации

| Проблема | Решение |
| --- | --- |
| Неоднозначность единиц измерения | Pint + кастомные словари + контекстное определение через БЯМ |
| Потеря точности при стемминге | Гибрид: словарь терминов + лемматизация для ПрО + стемминг для остальных |
| Аббревиатуры с несколькими значениями | Онтологии ПрО + словари + БЯМ |
| Замедление из-за баз знаний | Кеширование, пакетная потоковая обработка |
| Разные форматы дат | dateutil + pandas + кастомные правила |

Инструменты: pymorphy2, Mystem, spaCy, Pint, quantities, dateutil, pandas, SymPy, latex2sympy, RDKit.

## Токенизация

Цель: разбить нормализованный текст на минимальные значимые единицы (токены).

| Тип | Описание | Инструменты |
| --- | --- | --- |
| Словесная | По пробелам и пунктуации | `str.split()`, NLTK, spaCy |
| По предложениям | Смысловая целостность | NLTK, spaCy |
| Символьная | Для редких языков | — |
| Субсловная | BPE, WordPiece, Unigram | SentencePiece, HF tokenizers, tiktoken |
| LaTeX-aware | Защита формул | Кастомные парсеры + SymPy |
| Специализированная | Таблицы, числа с единицами, аббревиатуры | pandas, RDKit, кастомные правила |

Специфика промышленных текстов: числа с единицами, химические формулы, аббревиатуры — как единые токены.

### Эволюция методов токенизации

| Период | Подход |
| --- | --- |
| 1990–2000 | Словесная токенизация по пробелам |
| 2005–2015 | Учёт пунктуации, поддержка аббревиатур |
| 2015–2018 | BPE (Byte Pair Encoding) |
| 2018–2020 | WordPiece, Unigram (BERT, XLNet) |
| 2020–2023 | Специализированные: tiktoken, LaTeX-aware |
| 2024–наст. | Гибрид: кастомные правила + БЯМ, мультимодальная токенизация |

### Алгоритм токенизации

1. Предобработка:
   - определение типа токенизации (словесная / субсловная / гибридная);
   - защита формул маркерами;
   - извлечение таблиц в отдельную структуру;
   - объединение чисел с единицами в один токен.
2. Токенизация на предложения.
3. Словесная или субсловная токенизация:
   - классический поиск → словесная;
   - трансформеры → субсловная (BPE, WordPiece);
   - гибрид → словесная для терминов, субсловная для остальных.
4. Токенизация формул:
   - вариант 1: формула как один токен;
   - вариант 2: AST-токенизация;
   - вариант 3: LaTeX-aware с защитой команд.
5. Токенизация чисел и единиц: объединение в один токен `[NUMUNIT_N]`.
6. Токенизация аббревиатур: сохранение как целых токенов, добавление в словарь.
7. Восстановление защищённых элементов.
8. Валидация: сохранность терминов, формул, чисел.

### Проблемы и решения при токенизации

| Проблема | Решение |
| --- | --- |
| Редкие термины (OOV) | Субсловная токенизация, byte-level BPE, добавление в словарь |
| Разрыв формул | LaTeX-aware токенизация с защитой |
| Разрыв чисел с единицами | Маркеры `[NUMUNIT_N]` |
| Аббревиатуры | Словари + кастомные правила |
| Ограничение длины (512 токенов) | Семантическое разбиение с перекрытием, Longformer, BigBird |
| Мультиязычные документы | Мультиязычная токенизация |

Инструменты: SentencePiece, HF tokenizers, tiktoken, NLTK, spaCy, SymPy.

## Аугментация

Цель: увеличить объём и разнообразие данных, бороться с дисбалансом классов.

| Метод | Описание | Инструменты |
| --- | --- | --- |
| Замена синонимами | Словарная или контекстная | nlpaug, кастомные |
| Вставка/удаление слов | Создание вариаций | nlpaug |
| Перестановка слов | Устойчивость к порядку | `random`, кастомные |
| Back-translation | Перевод туда-обратно | MarianMT, OPUS |
| LLM-ориентированная | Перефразирование с сохранением смысла | GPT-4, Llama, Mistral |
| Контрастная | Сложные негативные примеры | SimCSE |
| Семантическая | Перефразирование, суммирование | T5, BART |
| Числовая | Изменение в диапазоне с сохранением размерности | numpy, Pint |
| Формульная | Эквивалентные преобразования | SymPy |
| Табличная | Изменение данных с сохранением структуры | pandas |
| Для редких классов | Целенаправленная генерация | imbalanced-learn |

### Эволюция методов аугментации

| Период | Подход |
| --- | --- |
| 2010–2015 | Простые лингвистические методы (NLTK, TextAugment) |
| 2015–2018 | Back-translation (Google Translate, MarianMT) |
| 2018–2020 | EDA (Easy Data Augmentation), доменные словари |
| 2020–2022 | Контрастное обучение (SimCSE) |
| 2022–2024 | БЯМ (GPT-3, ChatGPT) |
| 2024–наст. | Гибрид: локальные БЯМ (Llama, Mistral) + правила + ГЗ + онтологии |
| Перспектива | Мультимодальная аугментация (GPT-4o, Claude 3.5) |

### Алгоритм аугментации

1. Предварительный анализ: объём данных, баланс классов, типы.
2. Защита критических элементов:
   - числа и единицы — сохранять;
   - формулы — не изменять;
   - таблицы — сохранять структуру;
   - аббревиатуры — не изменять.
3. Базовые методы: синонимы (с базой знаний ПрО), вставка/удаление, перестановка, back-translation.
4. Специализированная аугментация:
   - числа в диапазонах ±10–20 %;
   - конвертация единиц;
   - эквивалентные преобразования формул (SymPy);
   - изменение данных в таблицах.
5. Аугментация с БЯМ: перефразирование, генерация редких классов, расширение контекста.
6. Валидация:
   - сохранение смысла ≥ 85 %;
   - точность чисел/формул = 100 %;
   - грамматика и логика ≥ 90 %.
7. Интеграция в датасет: добавление, перемешивание, сохранение метаданных.

### Проблемы и решения при аугментации

| Проблема | Решение |
| --- | --- |
| Синонимы не эквивалентны в ПрО | Доменные словари, онтологии, БЯМ с инструкцией сохранять термины |
| Изменение числовых параметров | Строгие диапазоны + валидация + экспертная оценка |
| Разрыв чисел с единицами | Защита маркерами |
| Разрыв формул | AST-преобразования через SymPy |
| Дорого использовать GPT-4 | Гибрид: локальные Llama/Mistral + GPT-4 для сложных случаев |
| Нереалистичные данные от БЯМ | Экспертная оценка + автоматическая проверка + LLM-as-a-judge |
| Дисбаланс классов | Целенаправленная генерация + контрастное обучение |

## Векторизация

Цель: преобразовать текст в числовые векторы для NLP-моделей.

| Группа | Модели | Применение |
| --- | --- | --- |
| Частотные | BoW, TF-IDF, BM25 | Классический поиск |
| Векторные | Word2Vec, GloVe, FastText | Плотные представления слов |
| Трансформерные | BERT, RoBERTa | Контекстные эмбеддинги |
| Поисковые | Sentence-BERT, E5, GTE | Семантический поиск, RAG |
| Мультимодальные | CLIP, ImageBind | Кросс-модальный поиск |
| Мультивекторные | ColBERT, ColBERTv2 | Точный поиск с деталями |
| Специализированные | MathBERT, Formula2Vec | Формулы (AST-векторизация) |

### Эволюция методов векторизации

| Период | Подход |
| --- | --- |
| 1990–2010 | BoW, TF-IDF |
| 2010–2015 | Word2Vec, GloVe, FastText (gensim, spaCy) |
| 2015–2018 | ELMo, ULMFiT (AllenNLP, fastai) |
| 2018–2020 | BERT, RoBERTa (Hugging Face) — точность ~ 88 % |
| 2020–2022 | Sentence-BERT, E5, GTE (sentence-transformers) — расцвет RAG |
| 2022–2024 | Мультивекторные (ColBERT), мультимодальные (CLIP, ImageBind) |
| 2024–наст. | Квантованные модели, гибридные системы, кеширование |

### Алгоритм векторизации

1. Предобработка: временная замена формул, чисел, таблиц маркерами.
2. Выбор метода: поиск / классификация / кластеризация / генерация + ресурсы.
3. Классическая векторизация:
   - TF-IDF (sklearn);
   - BM25 (Elasticsearch);
   - специальная обработка чисел.
4. Трансформерная векторизация:
   - RuBERT — для русского;
   - E5 / GTE — для поиска;
   - SBERT — для семантической близости;
   - пакетное кодирование + кеширование.
5. Специализированная векторизация:
   - AST-векторизация формул (SymPy → вектор);
   - таблицы: заголовки + типы + содержимое;
   - числа с единицами: сохранение размерности;
   - мультимодальная: CLIP / ImageBind.
6. Дообучение эмбеддингов: SimCSE, contrastive learning, Multiple Negative Ranking.
7. Оптимизация: PCA (≥ 90 % дисперсии), квантование Int8/Float16, индексация (FAISS, Qdrant, Milvus).
8. Валидация: MTEB, BEIR, RuMTEB; Hit Rate@10, MRR, NDCG.

### Проблемы и решения при векторизации

| Проблема | Решение |
| --- | --- |
| Не сохраняются точные числа | Отдельная индексация чисел + гибридный поиск с числовыми фильтрами |
| Потеря математической структуры формул | AST-векторизация + MathBERT |
| Высокая размерность (768–1024) | Модели с размерностью 384, квантование, PCA |
| Слабая адаптация к ПрО | Дообучение на доменных данных (SimCSE, E5) |
| Большие документы | Разбиение с учётом границ, Longformer, BigBird |
| Стоимость API | Кеширование эмбеддингов, локальные модели |

Инструменты: sklearn, sentence-transformers, E5, GTE, ColBERT, CLIP, ImageBind, SymPy, FAISS, Qdrant, Milvus, Elasticsearch.

## Ключевые принципы предобработки

- **Системность**: каждый этап влияет на качество всей системы.
- **Гибридность**: комбинация правил, ML и БЯМ даёт лучший результат.
- **Сохранение семантики**: формулы, числа, единицы, термины — неприкосновенны.
- **Достаточность**: выбирать минимально сложный инструмент, дающий требуемое качество.
- **Оценка качества**: на каждом этапе, с автоматическими метриками и LLM-as-a-judge.
- **Мониторинг**: отслеживание дрифта данных и деградации качества.
- **Масштабируемость**: распределённая обработка (Spark, Airflow).
- **Безопасность**: фильтрация PII, соответствие GDPR и ФЗ-152.
