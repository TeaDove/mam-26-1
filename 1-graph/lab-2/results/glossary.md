# Глоссарий к презентации «Предобработка текста для графа знаний»

Разделы идут по слайдам. В каждом пункте: **определение**, *наши цифры «грязный → чистый»*, **«Как считали»** —
алгоритм или формула. Значки у метрик на слайдах: ⋆ — считает LLM, ⋄ — алгоритм без LLM, ⊹ — гибрид (контекст
собирает обход графа, оценивает LLM).

## Слайды 1–2. Постановка эксперимента

1. **Граф знаний** — сеть, где вершины — понятия из текста, а рёбра — связи между ними с текстовым описанием.
2. **Вершина (сущность)** — понятие с названием, типом и описанием. *Пример: CONTROLLED ROLLING, тип «process».*
3. **Ребро (связь)** — утверждение, что две сущности связаны: «NIOBIUM — RECRYSTALLIZATION: ниобий тормозит
   рекристаллизацию».
4. **MinerU** — распознаёт PDF (текст, формулы, таблицы) и выдаёт markdown; формулы — в LaTeX, таблицы — в HTML.
   Общий вход обоих графов.
5. **GraphRAG** — библиотека Microsoft для построения графа из текста.
   **Как работает:** режет текст на фрагменты, для каждого фрагмента просит LLM перечислить сущности (название, тип,
   описание) и связи; сущности с одинаковым названием склеивает в одну вершину, описания объединяет.
6. **Экстрактор** — LLM, которая извлекает сущности и связи. У нас gpt-4o-mini, одна и та же для обоих графов.
7. **Грязный граф** — граф из markdown MinerU, из которого удалён только список литературы (иначе сравнение
   нечестное: литература даёт сотни вершин-авторов).
8. **Чистый граф** — граф из того же текста после пяти этапов предобработки, с теми же настройками GraphRAG.
9. **Пайплайн** — очистка → нормализация → chunking → токенизация → векторизация → GraphRAG. Очистка и нормализация
   работают с книгой целиком, chunking режет уже чистый текст.
10. **Токен** — кусочек текста, которым оперирует модель: слово, часть слова или символ. Размеры считаем
    токенизатором **o200k** — тем же, что у gpt-4o-mini.
11. **Эталон (gold)** — 4 страницы (по 2 из каждой книги), выверенные вручную по картинкам PDF и проверенные
    командой: текст страницы после идеальной очистки + списки величин и терминов после идеальной нормализации.
    На эталоне меряются этапы «по смыслу», а не количеством правок.
12. **RAG** — схема «найди подходящие фрагменты по векторам → ответь по ним». Следующий этап курса; сохранённые
    чанки и векторы — задел для него.

## Слайд 3. Очистка

13. **Очистка** — удаление того, что не несёт смысла: колонтитулов, номеров страниц, ссылок на картинки, HTML-сносок,
    маркеров ссылок на литературу, шапки с авторами; склейка разорванных абзацев и переносов. Каждая правка пишется
    в журнал (правило, было, стало).
14. **Регулярное выражение (regex)** — шаблон для поиска и замены текста. *Пример со слайда:
    `re.sub(r"</?(?:strong|u|b|i|em)>", "", text)` удаляет HTML-теги выделения.*
15. **Колонтитул** — строка, повторяющаяся на каждой странице («Tanaka: Controlled rolling of steel»).
    **Как находили:** строка длиной ≤ 80 символов, встречающаяся в книге ≥ 3 раз; блок, целиком равный такой строке,
    удаляется. Номер страницы — блок из 1–3 цифр (`^\d{1,3}$`).
16. **Разорванный абзац** — абзац, разрезанный переходом страницы или подписью к рисунку. *51 → 0.*
    **Как находили:** соседние абзацы (с пропуском подписей, колонтитулов и номеров) — разрыв, если левый не закончен
    точкой, а правый начинается со строчной буквы, цифры или формулы. Подпись к рисунку переносится после абзаца.
17. **Перенос** — слово, разбитое при вёрстке: «ох- лаждение», «con- trolled». *93 → 0.*
    **Как склеивали:** шаблон «буквы + дефис + пробел/разрыв + строчная буква»; английские слова склеиваются, только
    если склеенное слово есть в словаре или в тексте — настоящие составные («strain-induced») остаются с дефисом.
18. **PII** — персональные данные: шапка с авторами, аффилиации, e-mail, телефоны. *4 → 0.*
    **Как считали:** шаблоны e-mail, телефона, «инициалы + фамилия», фраз аффилиации («is with the», «д.т.н.»).
19. **Доля шумовых символов** — процент символов текста, попавших под шаблоны шума. *7,5% → 0,03%.*
    **Как считали:** помечаем символы, которые совпали с шаблонами: ссылки на картинки, HTML-теги, экранирование,
    битые и управляющие символы OCR, иероглифы, точки-заполнители в формулах, маркеры цитат `$^{1}$` и `[2]`,
    колонтитулы и номера страниц. Доля = помеченные символы / все символы.
20. **Служебные метки** — штучные элементы вёрстки (колонтитулы, номера, ссылки на картинки, маркеры цитат).
    *376 → 0.*
21. **CER / WER** — доля ошибок относительно эталона по символам / по словам.
    **Формула:** CER = (S + D + I) / N, где S, D, I — число замен, удалений и вставок в минимальной правке
    (расстояние Левенштейна), N — длина эталона. WER — то же по словам. *CER 9,8% → 0,3%, WER 15,1% → 3,1%.*
    **Как считали:** библиотека jiwer; сырой и очищенный текст страницы сравниваются с одним эталоном. Остаток — OCR,
    которую очистка не исправляет (индексы `T_ин` вместо `T_нп`), и дефис вместо тире.
22. **Точность, полнота, F1 удалений** — оценка «удалили ли то, что нужно, и только это».
    **Формулы:** точность = удалено верно / удалено всего; полнота = удалено верно / должно было уйти;
    F1 = 2 · точность · полнота / (точность + полнота). Блок «должен уйти», если его нет в эталоне; «ушёл», если
    его нет в очищенном тексте (сравнение по совпадающим кускам текста, difflib).
    *Удалено 13 из 13 нужных блоков, лишних 0: 100% / 100% / 100%.*
23. **Сохранность чисел, формул, ячеек таблиц** — проверка, что очистка не испортила содержание. *100% / 100% /
    100%.* **Как считали:** «ожидаемые» числа = числа сырого текста минус числа из удалённых блоков (по журналу);
    сохранность = доля ожидаемых, найденных в чистом тексте. Формулы — в каноническом виде, без пробелов.

## Слайд 4. Нормализация

24. **Нормализация** — одна запись для одного и того же: величины, аббревиатуры, термины. Формулы и таблицы на время
    замен закрываются маской, чтобы их не задеть.
25. **Величины в едином виде** — «730 °C», диапазон через тире «16–20 мм», «Н/мм²». *20% → 95%.*
    **Как считали:** широким шаблоном находим величины в любом виде (`730<sup>0</sup>С`,
    `$850 ^ { 0 } \mathbf { C }$`, `1000°C`); каноническая — совпадающая с шаблоном «число[–число] пробел единица».
26. **Глоссарий** — словарь «русская основа термина → канонический английский термин» и аббревиатур
    (`КП` → controlled rolling), файл `configs/glossary.yaml`.
27. **«Английский канон первым»** — главная находка. GraphRAG склеивает вершины только по точному названию. Если
    писать «аустенита (austenite)», модель называет вершину «АУСТЕНИТ»; работает только «austenite (аустенита)».
    **Как работает:** пометка ставится заново, если с прошлой прошло ≥ 3000 символов, — так она не зависит от
    будущего разбиения. **Как проверяли:** один фрагмент в трёх вариантах отправили в gpt-4o-mini с настоящим
    промптом GraphRAG и сравнили названия сущностей.
28. **Термины в обеих книгах** — термины глоссария, чьё английское название есть и в tanaka, и в stat3: будущие
    общие вершины графа. *0 → 23.*
29. **Лемма / лемматизация** — начальная форма слова (именительный падеж, единственное число) и приведение к ней.
    **Как работает:** лемматизируются только термины. Русский (pymorphy3): существительные, встречающиеся в книге
    ≥ 3 раз, и прилагательное прямо перед ними. Английский (spaCy): существительные во множественном числе →
    единственное. *Изменено 6,8% слов; полная лемматизация изменила бы 24% и ломала бы обороты («в то число») и
    глаголы.* Цена — русский текст становится неграмматичным («со скорость»), зато формы слова склеиваются в одну
    вершину.
30. **Точность приведения на эталоне** — доля величин и терминов эталона, найденных в нормализованном тексте в нужном
    виде. *Величины 9/9, термины 25/25.* Термины в ячейках таблицы не размечаются намеренно — таблица под маской.

## Слайд 5. Chunking

31. **Chunking (чанкинг)** — разбиение текста на фрагменты (чанки), которые по одному отдаются модели.
32. **Окна GraphRAG** — способ по умолчанию: каждые 1200 токенов с перекрытием (overlap) 100 токенов, не глядя на
    смысл. **Перекрытие** — сколько токенов конца прошлого чанка повторяется в начале следующего.
33. **Структурное разбиение** — по разделам и абзацам чистого текста. *28 → 36 чанков, в среднем 1137 → 691 токен,
    максимум 1053.*
    **Как работает:** текст разбирается на блоки (заголовок, абзац, формула `$$…$$`, таблица, картинка) по разделам.
    Блоки набираются в чанк, пока он ≤ 900 токенов; формулы и таблицы — неделимые. Граница ставится там, где левый
    блок кончается концом предложения, а правый не начинается со строчной буквы. Куски меньше 250 токенов
    приклеиваются к соседу, если сумма ≤ 1100; абзац длиннее 1100 токенов режется по предложениям.
34. **Доля границ, режущих предложение** — *100% → 3%: одна граница из 34.*
    **Как считали:** граница режет предложение, если она внутри абзаца не после конца предложения или между
    абзацами, когда левый не закончен (нет `.!?:;`) либо правый начинается со строчной буквы.
35. **Разрезанные формулы и таблицы** — позиция разреза попала строго внутрь формулы или таблицы. *6 → 0.*
36. **Эффект мелких чанков** — из фрагмента в 700 токенов модель извлекает больше сущностей на токен, чем из 1200:
    *10,2 → 17,0 вершины на 1000 токенов входа.* Поэтому часть роста графа — эффект разбиения, а не очистки.

## Слайд 6. Токенизация, векторизация, поиск

37. **Токенизация** — разбиение текста на единицы.
    **Как работает:** одно регулярное выражение с группами по порядку: HTML-разметка → формула целиком → число
    (с диапазонами) → слово (буквы, внутри дефис/апостроф) → прочий символ.
38. **OOV-rate** (out-of-vocabulary) — доля неизвестных слов. *1,39% → 1,00%; уникальных OOV 125 → 67.*
    **Как считали:** слово неизвестно, если его нет в частотном словаре wordfreq (частота 0) и в доменном глоссарии.
    После нормализации знаменатель — только исходные слова: вставленные английские термины не считаются.
39. **Обрывки формул** — непарные `$`, оставшиеся от разорванных OCR формул. *8 → 0.*
40. **Эмбеддинг** — вектор, которым нейросеть кодирует текст; близкие по смыслу тексты дают близкие векторы.
41. **bge-m3** — многоязычная модель эмбеддингов: текст → вектор из 1024 чисел длины 1. Векторы есть у каждого чанка
    и у каждой вершины графа («название: описание»), в граф записаны атрибутом `embedding`.
42. **Косинусное сходство** — cos(a, b) = a · b / (|a| · |b|), от −1 до 1; для векторов длины 1 — просто скалярное
    произведение.
43. **Сходство RU → EN, лучший чанк** — *0,611 → 0,666.* **Как считали:** для каждого русского чанка — максимум
    косинуса с английскими чанками, затем среднее. Часть роста дают вставленные английские термины.
44. **TF-IDF** — вектор текста без обучения: вес слова = частота в документе × редкость по коллекции.
    **Формула (scikit-learn):** idf = ln((1 + N) / (1 + df)) + 1, где N — число документов, df — в скольких есть
    слово; строки нормируются к длине 1. Документы — окна по 300 слов, одинаковые для обоих вариантов.
45. **Словарь TF-IDF** — число разных слов в коллекции. *2416 → 2155:* ушли обрывки слов и формы одного термина.
46. **Разреженность** — доля нулей в матрице «документы × слова»: 1 − ненулевые / (строки × столбцы).
    *0,936 → 0,930.*
47. **Hit@k** — доля вопросов, где правильный фрагмент попал в первые k результатов. *Hit@1: 35% → 65%.*
48. **MRR** (mean reciprocal rank) — среднее по вопросам от 1 / позиция первого правильного фрагмента.
    *0,59 → 0,77.*
49. **NDCG@10** — качество порядка первых 10 результатов: DCG = Σ rel_i / log₂(i + 1), делённое на DCG идеального
    порядка.
50. **Разложение 2 × 2** — поиск по 26 вопросам (оба языка) на четырёх вариантах: окна GraphRAG или структурные
    чанки × грязный или чистый текст. *MRR: окна 0,59 / 0,69, структура 0,70 / 0,77.* Разбиение и очистка дают
    примерно по +0,1. *Вопросы на другом языке: 0,52 → 0,72; 10 вопросов одногруппника: 0,54 → 0,70.*
    **Как считали:** вопрос и фрагменты кодируются bge-m3, фрагменты ранжируются по косинусу; фрагмент правильный,
    если содержит все ключевые признаки ответа.

## Слайд 7. Графы

**Как строится граф для всех метрик:** вершины — `entities.parquet` GraphRAG, рёбра — `relationships.parquet`.
Граф неориентированный; встречные связи A→B и B→A сливаются в одно ребро с обоими описаниями. Книга вершины — по
цепочке «вершина → фрагменты текста → документ»: только tanaka, только stat3 или обе. Метрики — библиотека NetworkX.

51. **Вершины из обеих книг (общие)** — вершины, извлечённые из фрагментов обеих книг. *5 → 15.*
52. **Русские вершины в крупнейшей компоненте** — вершины только из русской книги, попавшие в крупнейшую
    компоненту связности. *7 из 87 → 21 из 89:* книги сблизились, но большая часть русских вершин всё ещё отдельно.
    Прямых рёбер «английская — русская вершина» нет ни в одном графе: книги связаны только через общие вершины.
53. **Картинки графов** — силовая укладка (spring layout, алгоритм Фрюхтермана–Рейнгольда: рёбра тянут вершины друг
    к другу, вершины отталкиваются); цвет — книга (только английский текст, только русский, оба), размер — степень,
    подписаны крупнейшие хабы, изолированные вершины не показаны.

## Слайд 8. Сводная таблица: 8 критериев задания и обходы

**Окно обхода «2 × 3»** — от вершины BFS на 2 шага, на каждом шаге берём 3 соседа с наибольшим весом ребра: до 13
вершин. Окно — эти вершины, их описания и описания рёбер между ними.

54. **Полнота по тексту** ⋄ — доля терминов текста, которые стали вершинами. *57,8% → 65,6%.*
    **Как считали:** 120 английских и 60 русских терминов текста. Английские — сочетания из 2–3 слов подряд без
    стоп-слов и существительные (по разметке spaCy в предложении), где хотя бы одно слово редкое в общем языке
    (частота wordfreq < 4,5); русские — частые существительные и пары «прилагательное + существительное». Термин
    найден, если среди вершин есть совпадение лемм или косинус bge-m3 «термин — название вершины» ≥ 0,8.
55. **Непротиворечивость** ⊹ — доля вершин, где граф противоречит тексту. *41,7% → 30,8%.* Подробно — слайд 12.
56. **Корреференции** ⋄ — разные названия одного понятия. *Формы слова 14 → 19 вершин, переводы RU–EN 5 → 2;
    вершин-местоимений 0 и 0.* Подробно — слайд 11.
57. **Шум** ⋄ — доля вершин без терминологической нагрузки; вершины-формулы вынесены в отдельный подграф.
    *3,5% → 2,5%.* Подробно — слайд 11.
58. **Целостность формул и таблиц** ⋄ — собирается ли формула (таблица) в одной вершине или окне обхода.
    *Доля обозначений формулы в лучшем окне 2,8% → 11,2%; таблиц целых 0 из 1 и 0 из 1.* Подробно — слайд 11.
59. **Показатели графа** ⋄ — крупнейшая компонента и независимые циклы. *55%, 74 → 66%, 97.* Подробно — слайд 9.
60. **Покрытие ПрО** ⋄ — сколько из 40 ключевых понятий есть в графе. *80% → 92,5% по названиям, 57,5% → 65% по
    векторам названий.* Подробно — слайд 10.
61. **Вершины и рёбра по типам** ⋄ — *324 / 336, 13 типов → 424 / 437, 12 типов.*
62. **Обходы** ⋄ — пары понятий, связанные путём, и доля вершин русской книги в BFS-2. *5 из 6, 8% → 9 из 10, 20%.*
    Подробно — слайд 10.

## Слайд 9. Показатели графа и типы вершин

63. **Компонента связности** — группа вершин, где из любой можно дойти до любой. *62 → 84* (больше вершин —
    больше и компонент). **Алгоритм:** обход в ширину от каждой ещё не посещённой вершины, O(V + E).
64. **Изолированная вершина** — вершина без рёбер. *46 → 64.*
65. **Доля крупнейшей компоненты** — вершины самой большой компоненты / все вершины. *55% → 66%.*
66. **Степень вершины** — число её рёбер. *Средняя / максимальная 2,07 / 48 → 2,06 / 78.* **Хаб** — вершина с очень
    большой степенью; у нас CONTROLLED ROLLING, в чистом графе он собрал связи обеих книг.
67. **Лист** — вершина степени 1. *164 → 215:* граф GraphRAG — «звёзды» вокруг хабов.
68. **Мост** — ребро, после удаления которого граф распадается. *174 → 229.*
    **Точка сочленения** — такая же вершина. *67 → 78.*
    **Алгоритм (Хопкрофт–Тарьян):** один проход DFS; для каждой вершины — время входа и `low`, самое раннее время,
    достижимое из её поддерева по одному обратному ребру. Ребро к ребёнку — мост, если `low(ребёнка)` больше времени
    входа родителя; вершина — точка сочленения, если из поддерева ребёнка нельзя «перепрыгнуть» выше неё. O(V + E).
69. **Независимые циклы (цикломатическое число)** — E − V + C (рёбра − вершины + компоненты): сколько рёбер лишние
    сверх остовного леса, то есть сколько альтернативных путей. *74 → 97, но на 100 вершин 22,8 → 22,9:* рост
    пропорционален размеру графа, плотность (1,21 ребра на вершину) не изменилась.
    **Циклы через вершины обеих книг** — циклы минимального базиса, где есть вершина из обеих книг или вершины
    обеих языков. *29 → 71:* новые циклы сшивают книги. **Минимальный базис циклов** — набор независимых циклов
    наименьшей суммарной длины (алгоритм де Пины в варианте Кавиты и др., NetworkX); по нему считаются длины и
    состав циклов.
70. **Вершин на 1000 токенов входа** — вершины / входные токены × 1000. *10,2 → 17,0.*
71. **Вершины по типам** — подсчёт по полю `type`, которое проставил GraphRAG (процесс, параметр, фаза…);
    **рёбра по типам** — по парам типов концов. *Пар типов 54 → 59; персон 12 → 22 — мелкие чанки чаще выносят
    цитируемых авторов в вершины.*

## Слайд 10. Обходы и покрытие предметной области

72. **Обход графа** — систематический проход по вершинам от стартовой.
73. **BFS** (поиск в ширину) — идём «волнами»: соседи, потом соседи соседей. *В среднем 14 / 57 / 96 → 17 / 90 / 183
    вершин на 1, 2 и 3 шага.* **Алгоритм:** очередь; расстояние до каждой вершины = номер волны.
74. **DFS** (поиск в глубину) — идём по одной ветке до конца, потом возвращаемся. *Достижимо 160 → 245 вершин.*
    **Алгоритм:** стек (рекурсия); число вершин дерева обхода − 1 = сколько достижимо.
75. **Стартовые понятия** — ключевые понятия ПрО (controlled rolling, recrystallization, austenite, niobium…).
    **Как понятие находится в графе:** у каждого понятия список названий на двух языках и аббревиатуры; совпадение
    названия или его лемм без учёта регистра; среди нескольких кандидатов — вершина с наибольшей степенью.
76. **Кратчайший путь** — путь с наименьшим числом рёбер: в графе без весов это BFS от одного конца.
    **Двунаправленный поиск** — два BFS навстречу от обоих концов до встречи: та же длина, меньше просмотренных
    вершин.
77. **Пары понятий, связанные путём** — 10 заранее выбранных пар из разных частей ПрО; считаем связанные среди пар,
    где оба понятия есть в графе. Если понятие есть английской и русской вершиной, годится любая. *5 из 6 → 9 из 10:*
    в грязном для 4 пар одного из понятий нет совсем.
78. **Доля вершин русской книги в BFS-2** — среди вершин на расстоянии до 2 от ключевых понятий доля извлечённых из
    русской книги (только из неё или из обеих). *8% → 20%.*
79. **Покрытие предметной области (ПрО)** — *80% → 92,5% по названиям, 57,5% → 65% по векторам названий вершин.*
    **Как считали:** 40 ключевых понятий; по названиям — правило из п. 75; по векторам — косинус bge-m3 «понятие —
    название вершины» ≥ 0,8. **Оговорка:** 33 из 40 понятий — термины глоссария, нормализация вставляет их в чистый
    текст, поэтому рост отчасти по построению; `pearlite` в чистом графе потерян.
80. **Шумовые вершины в BFS-2** — доля шума среди вершин в 2 шагах от ключевых понятий. *0,5% → 1,1%:* шум висит на
    периферии.

## Слайд 11. Шум, корреференции, формулы

81. **Вершина-формула и подграф формул** — вершина, название которой — обозначение из формулы: одиночная буква
    (`B`, `N`), греческий символ (`Σ`, `ΣΕ`), «символ + нижний индекс» (`σ_{LH}`, `T_rs`, `Т_0`, `SIGMA_D`) или
    название с LaTeX-разметкой. Не формулы — химические элементы (`C`, `NB`), сокращения из глоссария (`RD`, `КП`),
    имена людей и организаций. **Как работает:** разметка регулярными выражениями; вершины-формулы выносятся в
    отдельный подграф и не участвуют в подсчёте шума и корреференций. *Формул 8 → 23; подграф чистого графа
    крепится к YIELD STRESS (9 рёбер) и TRANSITION TEMPERATURE (4).*
    Прошлая разметка пропускала `Т_0`, `Т_С`, `Г_Θ`, `SIGMA_D`, `DELTA_P` и ловила элементы и сокращения.
82. **Шум** — вершины без терминологической нагрузки среди вершин вне подграфа формул. *11 (3,5%) → 10 (2,5%);
    на 1000 токенов 0,35 → 0,40.* До выноса формул было 5,2% → 7,5%: рост давали именно формулы.
    **Как считали:** пять регулярных правил:
    1. только знаки и скобки;
    2. остатки LaTeX в названии (`DOUGLAS^2` — след ссылки на литературу);
    3. числа и единицы;
    4. местоимения и служебные слова;
    5. обрывки слов с дефисом: `НА-ГРЕВА`, если склеенное слово известно, а части — нет.

    Шестая проверка — слова нет ни в тексте, ни в частотном словаре (`ПЛАТОФОРМА`). Химические элементы не
    считаются шумом, имена людей и организаций — неизвестными словами.
    **Состав:** слова не из текста 7 → 9 (опечатки самой модели), числа 4 → 0 (индексы текстуры `{554}` в
    грязном), остатки LaTeX 0 → 1.
83. **Корреференция / дубликат** — разные названия одного понятия, ставшие разными вершинами.
    **Как считали** (по вершинам вне подграфа формул), три вида:
    - формы слова — группы с одинаковым ключом лемм: `C-MN-NB STEEL = C-MN-NB STEELS`; греческие буквы входят в
      ключ, поэтому `Γ-GRAIN` и `Α-GRAIN` — разные понятия. *14 → 19 вершин;*
    - синонимы на одном языке — пары названий с косинусом bge-m3 ≥ 0,92. *6 → 11 пар;*
    - переводы — пара «название кириллицей — название латиницей» с косинусом ≥ 0,85: `ДЕФОРМАЦИЯ = DEFORMATION`.
      *5 → 2 пары.*

    **Перебор порога 0,95…0,80:** переводы в чистом графе меньше при любом пороге до 0,85; ниже 0,85 появляются
    ложные пары. Пары на одном языке растут в обоих графах и быстрее в чистом: ниже 0,9 косинус ловит общее и
    частное понятие (`RECRYSTALLIZATION = STATIC RECRYSTALLIZATION`), а не дубликат. Поэтому пороги разные.
    Причина роста форм слова — модель пишет одно понятие в ед. и мн. числе и с дефисом/без; нужна склейка вершин
    после извлечения.
84. **Вершины-местоимения (BFS-3)** — вершины «он, она, это…».
    **Алгоритм:** такая вершина удаляется, её соседи подвешиваются к соседу с наибольшей степенью, считается её
    поддерево до глубины 3. *0 в обоих графах: GraphRAG местоимений не создаёт.*
85. **Целостность формул** — собирается ли формула в одной вершине или окне обхода.
    **Как считали:** формула → набор обозначений и чисел целыми токенами (`σ_{SH}` → `σsh`, числа от 3 знаков);
    формулы с одним обозначением пропускаются. «В вершине» или «в окне 2 × 3», если там ≥ 60% её токенов, иначе
    разорвана. *12 из 12 разорваны в обоих графах; в лучшем окне 2,8% → 11,2% обозначений.* В чистом графе есть
    вершины `Σ_{SH}`, `Σ_{PH}`, `K_Y`, но они разбросаны и не собираются в одно окно.
86. **Целостность таблиц** — так же по числам ячеек. *Единственная таблица разорвана в обоих: в лучшем окне 6,5% →
    13,3% её чисел.* Формулы и таблицы GraphRAG не сохраняет — это ограничение экстрактора, а не предобработки.

## Слайд 12. Непротиворечивость: контекст из графа → судья

87. **LLM-as-a-judge** — оценка результата другой, более сильной моделью по заданным критериям.
88. **Судья** — gpt-4.1, температура 0, ответ строго в JSON; для обоих графов одни промпты; ответы закэшированы.
    Готовых метрик судья не видит — только контекст из графа и текст.
89. **Непротиворечивость** ⊹ — *вершин с противоречиями 41,7% → 30,8%; терминов определены полностью 2,5% → 4,2%;
    противоречий всего 51 → 38.*
    **Как считали:**
    1. Выборка — 120 вершин на граф: ключевые понятия + случайные с фиксированным seed.
    2. Для вершины — её описание, окно BFS-2 (соседи, их описания, связи) и фрагмент текста, где название вершины
       (по основам слов) встречается чаще всего.
    3. Судья отвечает: определён ли термин полностью, частично или нет; сколько утверждений противоречат тексту.
       Утверждение, которого нет во фрагменте, — неполнота, а не противоречие.
90. **Стандартная ошибка разности долей** — SE = √(p₁(1 − p₁)/n₁ + p₂(1 − p₂)/n₂). *При 120 вершинах ≈ 6 п. п.;
    разница 11 п. п. ≈ 1,8 SE — на границе погрешности.*
91. **Типичное противоречие** — модель-экстрактор обобщает частное утверждение текста. *Грязный, NIOBIUM STEEL:
    «Nb-сталь измельчает зерно динамической рекристаллизацией», а текст — что в Nb-стали она почти невозможна.*

## Работа над ошибками, слайд 3. Чанки с пересечением

95. **Пересечение чанков (overlap)** — к чанку добавляется часть соседних чанков. *У нас по 7,5% слева и справа,
    итого +12,6% токенов.* **Как считали:** функция `with_overlap` берёт с края соседа целые предложения, пока
    их длина ближе всего к 7,5% длины чанка; формулы и таблицы — целиком или никак; край не режет предложение;
    чанк не длиннее 1200 токенов; соседи — только из той же книги. Базовые чанки не меняются.
96. **Повтор индексации** — тот же чистый вход, проиндексированный GraphRAG второй раз без кэша. Показывает шум
    самого GraphRAG: *вершин 424 и 389 на одном и том же тексте.*
97. **Явное отклонение** ⋄ — изменение метрики больше удвоенного шума и не меньше 3 п. п. для долей или 10% для
    счётчиков. **Как считали:** шум — наибольшая разница «база — повтор» по чистому графу и «база — вариант» по
    грязному графу, который не менялся (`lab2 variants`).
98. **Бюджет сущностей на чанк** — экстрактор берёт с чанка примерно одно число сущностей (15–16) при любой
    длине. *С пересечением часть бюджета уходит на повтор соседа: вершин 424 → 346, рёбер 437 → 455.*
99. **Звёздный рост циклов** — новые циклы проходят через одну вершину-хаб, а не образуют новую структуру.
    *Циклов на 100 вершин 22,9 → 43,1, но через CONTROLLED ROLLING — 70% циклов против 60%.*
100. **Сходство соседних чанков** ⋄ — средний косинус векторов bge-m3 соседних чанков одной книги.
     *0,756 → 0,811:* чанки стали похожи, поэтому MRR поиска упал 0,77 → 0,73.

## Если спросят

- **Почему раньше шум в чистом был выше?** Из целых формул модель сделала вершины-обозначения (`Σ_{LH}`). Их
  разметили регулярными выражениями и вынесли в подграф формул — без них шум ниже в чистом графе.
- **Почему не понизить порог косинуса?** Переводы при 0,85 действительно ловятся точно, а на одном языке ниже 0,9
  косинус ловит родственные понятия, а не дубликаты. Поэтому пороги разные: 0,92 и 0,85.
- **Почему циклов больше?** Ровно пропорционально размеру графа (22,8 и 22,9 на 100 вершин); новые циклы
  проходят через вершины обеих книг.
- **Почему вершин больше, а не меньше?** Чистый текст пришёл мелкими чанками: модель видит меньше текста за вызов и
  извлекает больше сущностей на токен. Поэтому счётчики приведены и на 1000 токенов.
- **Почему дубликатов больше?** Лемматизация текста не мешает модели писать одно понятие в ед. и мн. числе.
- **Почему таблица не нормализована?** Таблица закрыта маской, чтобы не менять ячейки: термины `КП`, `КП+УО`
  в ячейках остаются как есть.
- **Почему gpt-4o-mini?** Чтобы графы были сравнимы с первой версией и отличалась только предобработка.
- **Пересечение чанков помогло?** Наполовину: граф связнее (крупнейшая компонента 66% → 77%, русских вершин в
  ней 21 → 49), но вершин меньше, полнота −6 п. п., MRR 0,77 → 0,73. Для RAG оставили чанки без пересечения.
- **А если удалить вершины-формулы после GraphRAG?** Проверили: почти ничего не меняется (чистый граф 424 → 401
  вершина, циклов на 100 вершин 22,9 в обоих случаях, шум и покрытие те же). Формулы — в основном листья.
- **Почему судья — другая модель?** Чтобы модель не оценивала саму себя.
