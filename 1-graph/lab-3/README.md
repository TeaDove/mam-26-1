# Лабораторная 3 (ДЗ-2) — RAG на графе знаний с графовой нейронной сетью: отчёт

## 1. Цель и постановка

Цель — поработать с графовыми нейронными сетями (GNN): обучить GNN на своём графе знаний и встроить её в
RAG-архитектуру, которая отвечает на вопросы пользователя по этому графу.

Требования из лекции (полностью — [TASK.md](TASK.md)):

- пользователь задаёт вопрос обычным текстом; вопрос превращается в граф запроса;
- контекст в графе знаний находит **обученная GNN**, а не обходы графа;
- промпт формируется автоматически и требует от LLM отвечать строго по контексту из графа;
- база знаний — граф из прошлой работы; узлы представлены векторами признаков;
- качество оценивается автоматической метрикой, порог — **не меньше 60% правильных ответов**;
- платные ресурсы и мощная LLM не требуются.

Решения, которые лекция оставила открытыми, согласованы до начала работы (`TASK.md`, раздел 6): оба графа из лабы 2,
GAT с задачей предсказания связей, локальная Qwen2.5-14B как генератор и судья, 26 вопросов с эталонными ответами,
базовая линия без GNN.

## 2. Данные

**Графы знаний** — из [лабы 2](../lab-2): GraphRAG (gpt-4o-mini) по двум учебникам о контролируемой прокатке стали
(`tanaka1981` — английский обзор, `stat3` — русская статья), оба учебника в одном графе.

| Граф | Как построен | Вершин | Рёбер |
| --- | --- | --- | --- |
| грязный | GraphRAG по тексту MinerU без предобработки | 324 | 336 |
| чистый | GraphRAG после очистки, нормализации и разбиения на чанки | 424 | 437 |

Кроме вершин и рёбер, у каждой вершины есть атрибут — ссылки на фрагменты исходного текста (text units GraphRAG),
из которых она извлечена.

**Вопросы** — 26 вопросов из лабы 2 (16 на английском, 10 на русском; 16 по `tanaka1981`, 10 по `stat3`). К каждому
выписан эталонный ответ по тексту учебника и две регулярки: `evidence` — по ней находим фрагменты текста с ответом,
`key` — ключевой факт эталона (число, название). Всё — в `configs/questions.yaml`.

## 3. Метод

```
вопрос (RU/EN)
  → граф запроса: Qwen2.5-14B выделяет сущности и связи (те же типы сущностей, что у графа знаний)
  → поиск: эмбеддинги вершин запроса и графа знаний → top-5 похожих вершин на каждую вершину запроса
           + бонус, если связь из запроса есть в графе (ребро +0,1, общий сосед +0,05)
  → контекст: 3 стартовые вершины + окрестность радиуса 1–2, не больше 30 вершин, рёбра между ними,
              2 исходных фрагмента текста стартовых вершин
  → промпт «отвечай только по контексту, иначе — „В контексте нет ответа“» → ответ Qwen2.5-14B
  → судья Qwen2.5-14B сравнивает ответ с эталоном: правильно / частично / неправильно
```

**Признаки вершин** — эмбеддинги bge-m3 (1024) от строки «название: описание», нормированные по L2.

**GNN.** Задача обучения — предсказание связей: размеченных классов у вершин графа нет, а рёбра есть. Рёбра делятся
80/10/10 на обучение, валидацию и тест. На каждой эпохе к каждому обучающему ребру берётся отрицательная пара: та же
начальная вершина и случайная, не связанная с ней ни одним **обучающим** ребром. Оценка связи — косинус эмбеддингов
концов ребра, умноженный на 10 (косинусный декодер): GNN учится в той же метрике, по которой потом идёт поиск.
Функция потерь — бинарная кросс-энтропия; ранняя остановка по ROC-AUC на валидации.

| Параметр | GAT (основная) | GraphSAGE (сравнение) |
| --- | --- | --- |
| слои | 2 | 2 |
| головы внимания | 8 | — |
| скрытый слой / выход | 64 × 8 / 64 | 512 / 64 |
| dropout, активация | 0,3, ELU | 0,3, ELU |
| оптимизатор | Adam, lr 0,005, weight decay 5·10⁻⁴ | то же |
| эпох | до 300, остановка через 30 без улучшения | то же |
| сиды | 5, эмбеддинги усредняются | 5 |

**Вершины запроса** получают эмбеддинги той же GNN индуктивно: на вход идут их признаки bge-m3 и рёбра графа запроса.

**Способы поиска:**

| Поиск | Вектор вершины |
| --- | --- |
| `bge-m3` | только признаки bge-m3 — базовая линия без GNN |
| `gat`, `sage` | только эмбеддинги GNN |
| `hybrid` — основной | bge-m3 с весом 0,7 и GAT с весом 0,3 (скалярное произведение = взвешенная сумма косинусов) |

**Метрики:**

- **Правильно** — доля ответов, которые судья признал правильными (порог задания — 60%); «правильно или частично» —
  для справки.
- **MRR, Hit@k** — ранг первой релевантной вершины; релевантна вершина, извлечённая из фрагмента текста с ответом.
- **Контекст содержит релевантную вершину** — доля вопросов, где такая вершина попала в контекст.
- **Факт в графе / в контексте** — есть ли ключевой факт эталона в описаниях вершин и рёбер всего графа / в
  контексте, отданном LLM.

Все модели работают локально на рабочем ПК с видеокартой (8 ГБ): bge-m3 — sentence-transformers, GNN — PyTorch
Geometric, Qwen2.5-14B — Ollama.

## 4. Ход работы

1. **Первый прогон** — контекст только из вершин и рёбер, GNN с одним сидом. Правильных ответов не больше 27%
   (чистый граф, bge-m3), с GNN — 12–19% (`results/graph_only_v1/`). Разбор показал две причины:
   - **в графе нет многих фактов:** GraphRAG при извлечении теряет числа («730–800 °C», «5+3», «10–30 °C/с»), и
     ключевой факт эталона есть в описаниях чистого графа только у 54% вопросов — это потолок для контекста из графа;
   - **GNN ищет хуже bge-m3 и сильно зависит от сида:** MRR на чистом графе 0,49 у GAT против 0,74.
2. **Две поправки** (`TASK.md`, раздел 6):
   - в контекст добавлены 2 исходных фрагмента текста стартовых вершин — атрибут вершины, так же работает local
     search в GraphRAG; поиск по-прежнему делает GNN;
   - основной поиск — гибрид bge-m3 + GAT, GNN обучается с 5 сидами и усредняется.
3. **Проверка вариантов GNN без LLM.** Residual-соединения в GAT не дали устойчивого прироста в предсказании связей
   (разброс между сидами больше разницы). Веса гибрида 0,1–0,3 и выбор соседей по оценке связи от GAT не обогнали
   bge-m3 на чистом графе: ключевой факт попадал в контекст в 19–21 вопросе из 26 против 24 у bge-m3. Оставлены
   согласованные настройки.
4. **Воспроизводимость.** Порядок связей в промпте зависел от рандомизации хешей Python (`subgraph(set)` в
   networkx), поэтому промпт менялся от запуска к запуску, а с ним — ответы. Связи теперь идут в порядке вершин
   контекста (тест `test_relations_follow_context_order`), все ответы пересчитаны.
5. **Новое обучение GNN** — идея и код одногруппника: косинусный декодер вместо скалярного произведения и
   отрицательные пары, которые не попадают на существующие рёбра. В исходном варианте отрицательные пары исключали
   все рёбра графа, включая валидационные и тестовые, — это утечка, она завышала ROC-AUC и влияла на раннюю
   остановку. Исправлено: исключаются только обучающие рёбра. Разбор без LLM показал, что прирост даёт именно новое
   обучение, а не другие изменения патча (более сильная удалённая LLM и её графы запросов); их не брали, чтобы
   цифры оставались сравнимыми. Добавлена команда `lab3 retrieval` — метрики поиска без LLM. Прежние результаты —
   `results/before_cosine_training/`.
6. **Ручная проверка судьи** — 78 ответов: гибрид на обоих графах и bge-m3 на чистом.

## 5. Результаты

### 5.1. Предсказание связей

ROC-AUC на тестовых рёбрах, среднее ± отклонение по 5 сидам. Базовая линия — косинус признаков bge-m3 без обучения
на тех же разбиениях.

| Граф | GNN | Косинус bge-m3 | GNN, валидация | GNN, тест |
| --- | --- | --- | --- | --- |
| грязный | GAT | 0,797 ± 0,055 | 0,785 ± 0,053 | 0,773 ± 0,017 |
| грязный | GraphSAGE | 0,780 ± 0,077 | 0,622 ± 0,071 | 0,551 ± 0,071 |
| чистый | GAT | 0,809 ± 0,043 | 0,722 ± 0,049 | 0,697 ± 0,030 |
| чистый | GraphSAGE | 0,784 ± 0,016 | 0,554 ± 0,045 | 0,545 ± 0,062 |

GNN по-прежнему предсказывает связи не лучше косинуса bge-m3; GAT заметно стабильнее GraphSAGE. Новое обучение
улучшило не предсказание связей, а поиск (раздел 5.2).

### 5.3. Проверка судьи

78 ответов проверены вручную (`results/manual_check.json`): гибрид на обоих графах и bge-m3 на чистом. Флаг
«правильно» совпал с судьёй в 74 случаях из 78. Судья ошибается в обе стороны: засчитывает ответ на f06, где названа
область без рекристаллизации, но не «стадия 2», и ставит «частично» на f08, где ключевой факт («внутри зёрен и на
границах») есть. По ручной проверке правильных ответов: гибрид — 62% на чистом и 65% на грязном графе, bge-m3 на
чистом — 65%. Порог 60% проходят все три варианта.

### 5.4. Примеры

- **r09** «Сколько проходов делают в чистовой клети до и после ускоренного охлаждения по схеме КП+УО+КП?» Граф
  запроса: КП+УО+КП — проходы. Стартовые вершины гибрида на чистом графе: УО, КП, КП+УО+КП. Ответ: «до ускоренного
  охлаждения делают 5 проходов, а после — 3» — правильно. Числа «5+3» нет в описаниях вершин, оно пришло из таблицы
  в исходном фрагменте текста.
- **f02** «What accelerated-cooling rate after deformation is reported for thick plate?» Старое обучение уводило
  гибрид от нужного фрагмента, и модель отвечала «В контексте нет ответа». С новым обучением стартовые вершины —
  HEAVY PLATE, ACCELERATED COOLING, THICKNESS, ответ «10–30 °C/s» — правильно.
- **f07** «What feature divides unrecrystallized austenite grains during controlled rolling?» На грязном графе гибрид
  находит фрагмент про полосы деформации и отвечает правильно, bge-m3 — нет. На чистом графе обе модели выбирают
  общие вершины про контролируемую прокатку и отвечают «нет ответа».
- **f06** «Which controlled-rolling stage uses the non-recrystallization region?» Модели находят вершину
  NON-RECRYSTALLIZATION REGION, но не называют «стадию 2» — частично: формулировку берут из описания вершины.

## 6. Анализ

1. **С новым обучением GNN порог 60% проходит основной вариант с GNN:** гибрид — 65% по судье на обоих графах, по
   ручной проверке 62% на чистом и 65% на грязном. Без GNN (bge-m3) на чистом графе — 62% по судье, 65% вручную.
2. **На чистом графе гибрид сравнялся с bge-m3, на грязном — заметно лучше.** На чистом графе факт попадает в
   контекст одинаково часто (77%), а контекст гибрида чаще содержит релевантную вершину (96% против 92%). На грязном
   графе гибрид даёт 65% правильных против 31% у bge-m3: описания вершин там беднее, и структура графа добавляет
   информацию.
3. **Главное — согласовать обучение GNN с поиском.** Со скалярным произведением GNN училась на шкале, которая не
   совпадает с косинусом при поиске, и гибрид на чистом графе давал 42%. Косинусный декодер убрал это расхождение;
   предсказание связей при этом не улучшилось, а поиск — да.
4. **Одна GNN без текстовых признаков ищет хуже bge-m3** (MRR 0,41–0,42 против 0,60–0,74): на графе в 300–400
   вершин с ~1 ребром на вершину GNN не может выучить смысловую близость; полезна она как добавка к bge-m3.
5. **Предобработка из лабы 2 окупилась:** ключевых фактов в описаниях чистого графа 54% против 31%; с bge-m3
   правильных ответов 62% против 31%.
6. **Контексту из графа GraphRAG нужен исходный текст:** без него не больше 27% правильных — описания вершин
   обобщают текст и теряют числа, формулы и таблицы.
7. **LLM-генератор ведёт себя аккуратно:** если факт есть в контексте, Qwen2.5-14B обычно отвечает правильно; если
   нет — пишет «нет ответа», а не выдумывает. Типичная ошибка — общая формулировка вместо конкретного факта (f06).

## 7. Выводы

- RAG-архитектура с GNN собрана и работает от вопроса до ответа: граф запроса, поиск через GAT, контекст из графа и
  исходного текста, ответ и автоматическая оценка — всё локально.
- Порог 60% достигнут основным вариантом с GNN (гибрид bge-m3 + GAT) на обоих графах: 65% по судье, 62–65% по
  ручной проверке.
- GNN полезна как добавка к текстовым эмбеддингам, если её обучение согласовано с метрикой поиска; сильнее всего
  она помогает там, где текстовые признаки слабые (грязный граф).
- Дальше можно пробовать обучение, которое прямо сохраняет близость текстовых признаков (контрастное), и разметку
  «вопрос — релевантные вершины» для обучения с учителем.

## 8. Ограничения

- 26 вопросов: один ответ — это 4 п. п.; 62% и 65% отличаются на один ответ.
- Судья — та же модель, что отвечает; ручная проверка сделана для трёх вариантов из восьми.
- Обучение GNN на CPU не воспроизводится бит в бит (недетерминированная агрегация в PyTorch Geometric): между
  запусками чистый GAT заметно меняется (на чистом графе факт в контексте 50–69%), гибрид — меньше. Таблицы получены
  на моделях одного запуска, метрики обучения усреднены по 5 сидам.
- Вес гибрида 0,3 выбран до прогона и не подбирался по этим вопросам.

## 9. Воспроизведение

Нужны Python 3.12, `uv`, видеокарта для bge-m3 и LLM с OpenAI-совместимым API — по умолчанию Ollama с
`qwen2.5:14b-instruct` (адрес — `LAB3_LLM_BASE_URL`, ключ — `LAB3_LLM_API_KEY`, модель — `LAB3_LLM_MODEL` и
`LAB3_JUDGE_MODEL`). Если Ollama занимает видеопамять, этапы `retrieval` и `rag` запускаются с `LAB3_DEVICE=cpu`.
Ответы LLM кешируются в `data/llm_cache/` с учётом адреса API.

```bash
uv sync
uv run lab3 features   # признаки bge-m3 вершин обоих графов → data/*_features.npy
uv run lab3 train      # GAT и GraphSAGE, 5 сидов, предсказание связей → results/metrics/link_prediction.json
uv run lab3 queries    # графы запросов → results/query_graphs.json
uv run lab3 retrieval  # MRR, Hit@k, контекст и факт в контексте без LLM → results/metrics/retrieval.json
uv run lab3 rag        # поиск, ответ и судья для 2 графов × 4 способов → results/answers, results/metrics/rag.*
uv run lab3 ask "Какой элемент замедляет рекристаллизацию аустенита?" --graph clean --retriever hybrid
uv run pytest && uv run ruff check . && uv run ruff format --check .
```
