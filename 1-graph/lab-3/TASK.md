# ДЗ-2: RAG на графе знаний с графовой нейронной сетью — техническое задание

Источник — лекция 21.10.2026 (расшифровка записи не в репозитории; метки `[мм:сс]` — время в записи).
Разделы 1–5 — требования преподавателя, только то, что прозвучало на лекции. Раздел 6 — наши решения там, где
лекция молчит, согласованные до начала работы, и две поправки, принятые по результатам первого прогона.

## 1. Цель

Поработать с графовыми нейронными сетями (GNN): поднять GNN, обучить её на своём графе знаний и встроить в
RAG-архитектуру, которая отвечает на вопросы пользователя по этому графу `[05:00–09:05]`, `[51:52]`.

## 2. Что должно получиться: RAG-архитектура

Блоки `[05:00–06:40]`:

1. **Пользователь** задаёт вопрос на русском языке, обычным текстом, как в чате с LLM.
2. **База знаний** — граф знаний. На запрос она отдаёт контекст — фрагмент графа.
3. **Генеративная LLM** получает автоматически сформированный промпт с этим контекстом и отвечает **строго в
   рамках контекста** из графа.

Поток данных `[06:40–08:56]`:

| № | Шаг | Чем делается | Вход → выход |
| --- | --- | --- | --- |
| 1 | Вопрос → граф запроса | сервис построения графа, «можно тем же GraphRAG» | текст вопроса → граф запроса |
| 2 | Поиск контекста | **обученная GNN** | граф запроса + граф знаний → релевантный фрагмент графа знаний |
| 3 | Промпт | обычный (классический) алгоритм | фрагмент графа → промпт |
| 4 | Ответ | генеративная LLM | промпт → ответ пользователю |

## 3. Обязательные требования

| № | Требование | Где на лекции |
| --- | --- | --- |
| R1 | База знаний — **граф, построенный в ДЗ-1** («основной граф у вас построен уже на ДЗ-1») | `[08:10]` |
| R2 | Контекст ищет **GNN**, а не обходы графа и не специальные NLP-технологии | `[06:40]`, `[08:10]` |
| R3 | GNN **обучается на графе знаний**, затем совмещает граф запроса с тем, что выучила, и находит в графе знаний фрагмент, соответствующий запросу | `[06:40]` |
| R4 | GNN решает одну из типовых задач на графах: классификация/предсказание узлов, рёбер (связей) или графа (подграфа) | `[06:40]`, `[16:47]`, `[42:07]` |
| R5 | Каждый узел представлен **вектором признаков (эмбеддингом)** — GNN работает только с числами; на вход подаются матрица смежности и матрица признаков узлов. Признаки рёбер — по необходимости | `[18:48]`, `[33:00–37:26]`, `[38:08]` |
| R6 | Граф строится **и для запроса** (не только для базы знаний) | `[08:10]`, `[08:56]` |
| R7 | Промпт формируется автоматически и требует от LLM ответа строго по контексту из графа | `[06:40]` |
| R8 | **Оценка RAG автоматической метрикой** (пример — MRR; «любую выберите») | `[51:07–51:45]`, `[63:06]` |
| R9 | Результат оценки — **не ниже 60% правильных (корректных) ответов** | `[63:06]` |

Явно **не требуется** `[05:00]`:
- платные ресурсы;
- высокое качество графа;
- «суперхорошая» LLM.

Экспертная оценка «задал вопрос — посмотрел ответ» допускается в дополнение к метрике, но не вместо неё
`[51:13]`.

## 4. Выбор GNN и настройки (рекомендации преподавателя)

- Архитектура — любая из четырёх: GCN, GAT, GraphSAGE, GIN `[53:00–54:43]`, `[63:06]`.
- Рекомендована **GAT** (Graph Attention Network) — «самая менее капризная, с достаточно хорошим решением».
- Простую GCN брать не советуют: оценки RAG будут слабые.
- GIN (изоморфная) — самая капризная в обучении, но допустима.
- GraphSAGE умеет отдавать эмбеддинги узлов на выходе `[60:34]`.
- Слоёв 2–4; для GAT на небольшом графе хватит 2–3. Больше слоёв — переусреднение (oversmoothing) `[15:20]`,
  `[39:26]`, `[58:46]`.
- Головы внимания GAT: начать с 8, при нехватке — до 16 `[60:34]`.
- Размер скрытого слоя 16–256. Dropout. Функции активации: ReLU, ELU, на выходе классификации — softmax
  `[49:08]`, `[55:48]`.

Если метрики плохие, по порядку `[52:03]`, `[58:05]`:

1. Проверить нормализацию признаков: векторы слишком большие или разреженные. Попробовать batch normalization и
   layer normalization.
2. Проверить инициализацию весов.
3. Уменьшить число слоёв.

Стратегии сопоставления запроса с графом `[63:06]` — на выбор:

- **(а) поэтапно** — сначала похожие узлы, затем среди них похожие отношения. Вероятность найти совпадение выше.
- **(б) целиком** — сразу искать в графе знаний подграф, похожий на граф запроса.

## 5. Критерий приёмки

- Работает весь поток из раздела 2, от вопроса на русском до ответа LLM.
- Контекст для ответа выбирает обученная GNN.
- Автоматическая оценка показывает ≥ 60% правильных ответов (R9). Если нет — исправлять GNN по советам
  из раздела 4.

## 6. Решения там, где лекция молчит

| № | Вопрос | Решение |
| --- | --- | --- |
| D1 | Какой граф — «ДЗ-1»? | **Оба графа лабы 2** (`1-graph/lab-2`): грязный (324 вершины) и чистый (424 вершины); сравниваем, какой лучше |
| D2 | Признаки узлов | bge-m3 (1024) от «название + описание» вершины; L2-нормализация. Признаки рёбер не используем в первой версии |
| D3 | Задача GNN | **Предсказание связей** (link prediction) — самообучение без ручной разметки: рёбра графа делятся на train/val/test, отрицательные пары сэмплируются. Выход — структурные эмбеддинги узлов |
| D4 | Архитектура | **GAT**, 2 слоя, 8 голов, скрытый слой 64, dropout 0,3, ELU; PyTorch Geometric. Вариант для сравнения — GraphSAGE |
| D5 | Граф запроса | Сущности и связи из вопроса извлекает та же LLM с промптом GraphRAG (типы сущностей те же, что у графа знаний). Если сущностей < 2 — граф из одной вершины |
| D6 | Совмещение запроса и графа | Стратегия **(а)**: узлы запроса получают эмбеддинги той же GAT (индуктивно: признаки bge-m3 + рёбра графа запроса); top-5 похожих вершин графа знаний по косинусу; затем бонус за совпадение отношений; 3 стартовые вершины; контекст — их окрестности радиуса 1–2, не больше 30 вершин. **Поправка 2:** основной поиск — **гибрид**: вектор вершины = bge-m3 (вес 0,7) + среднее GAT по 5 сидам (вес 0,3); чистый GAT и GraphSAGE — строки сравнения |
| D7 | Промпт | Вершины с описаниями и рёбра с описаниями найденного подграфа; инструкция «отвечай только по контексту; если ответа нет — так и скажи». **Поправка 1:** плюс 2 исходных фрагмента текста стартовых вершин (text units GraphRAG — атрибут вершины, как в local search) |
| D8 | LLM | Локальная Qwen2.5-14B-Instruct (Ollama) |
| D9 | Набор вопросов | 26 вопросов лабы 2 + эталонные ответы, выписанные из текста (`configs/questions.yaml`) |
| D10 | Метрики | **Правильность ответа** (доля правильных, судья — та же локальная Qwen2.5-14B по эталону + ручная проверка ответов на чистом графе) — для порога 60%; **MRR / Hit@k** — нашла ли GNN вершины, связанные с эталонным ответом; плюс метрики link prediction (ROC-AUC) на test-рёбрах |
| D11 | Базовая линия | Тот же RAG, но вершины ищутся косинусом bge-m3 без GNN — чтобы показать вклад GNN |
| D12 | Где делать | Новая папка `1-graph/lab-3` в репозитории; обучение GNN, эмбеддинги и LLM — на рабочем ПК с видеокартой |

Почему поправки. Первый прогон (контекст только из графа, один сид) дал не больше 27% правильных ответов: ключевой
факт эталона есть в описаниях вершин и рёбер только у 18 вопросов из 26 — GraphRAG теряет числа. Обученная GNN
одна искала хуже, чем косинус bge-m3, и сильно зависела от сида. Результаты первого прогона —
`results/graph_only_v1/`.
