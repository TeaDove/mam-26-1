# RAG на графе знаний с графовой нейронной сетью

## План защиты · 6 минут

**Начало.** «Мы обучили графовую нейросеть на двух графах из прошлой лабораторной и использовали её эмбеддинги
для поиска фактов. Гибридный поиск дал по 17 верных ответов из 26 на каждом графе».

| Слайд | Время | Что сказать |
| --- | --- | --- |
| 1. Задача | 0:20 | Нужно отвечать на вопросы по графу знаний, задействовать обученную GNN в поиске и набрать 60% верных ответов. |
| 2. Данные | 0:30 | Оба графа построены по одним источникам о прокатке стали. Предобработка меняет граф и фрагменты текста. В каждом прогоне одни и те же 26 вопросов. |
| 3. Схема | 0:45 | Пройдите по стрелкам. Qwen строит граф запроса. GAT кодирует оба графа. Вес текста — 70%, вес GAT — 30%. По найденным вершинам собираем подграф и исходный текст. |
| 4. Обучение | 0:45 | Откладываем часть рёбер. Модель учится ставить известные рёбра выше случайных пар. Декодер использует косинус, как и поиск. Состояние модели выбираем по ROC-AUC на валидации. |
| 5. Метрики GNN | 0:30 | На тех же тестовых парах GAT обходит GraphSAGE, а косинус bge-m3 лидирует. Предсказание связей и поиск доказательств для ответа — разные задачи. |
| 6. Проблемы | 0:35 | При построении графа терялись числа, мера сходства при обучении отличалась от поиска, порядок рёбер менял промпт. Назовите исправления. |
| 7. Поиск | 0:30 | На грязном графе гибрид находит ключевой факт для 17 вопросов, bge-m3 — для 10. MRR почти не меняется. Ранг первой нужной вершины и состав итогового контекста — разные измерения. |
| 8. Ответы | 0:40 | Покажите порог 60%. У гибрида 17/26 на обоих графах, у bge-m3 на чистом — 16/26. При ручной проверке на чистом графе порядок меняется. |
| 9. Ragas | 0:35 | Объясните точность и полноту по ID. На грязном графе растут обе метрики. На чистом полнота немного выросла, а точность снизилась. |
| 10. Пример | 0:30 | Спросите, сколько чистовых проходов в схеме. В графе есть схема, а числа 5 и 3 нашлись в исходной таблице. |
| 11. Вывод | 0:20 | Самый большой выигрыш на грязном графе. Отдельные GNN дали меньше 60%. Выборка мала, а фрагменты размечены по шаблонам. |

**Как считается порог 60%.** Берём долю полностью верных ответов по сравнению с эталоном. Частично верные
считаются отдельно. На 26 вопросах достаточно 16 верных ответов.

**Что изменилось в обучении.** Модель ответа и графы запросов были теми же. Декодер и выбор отрицательных пар
поменялись одновременно. Сравнение показывает их совместный эффект.

**Зачем несколько видов оценки.** Тестовый AUC измеряет ранжирование рёбер, точность и полнота по ID — выбор
фрагментов, а судья оценивает итоговые ответы. У этих метрик разные цели.

## Глоссарий · данные, модели и поиск

| Термин | Значение в этой работе |
| --- | --- |
| Граф знаний | Сеть сущностей и связей, извлечённых из исходных документов. |
| Вершина / сущность | Объект в графе, например ускоренное охлаждение. У вершины есть имя, описание и ссылки на текст. |
| Ребро / связь | Отношение между вершинами. GNN обучается на неориентированных рёбрах и признаках вершин. |
| Подграф | Выбранные вершины и связи между ними. Их передают модели в текстовом виде. |
| Граф запроса | Небольшой граф сущностей и связей из вопроса пользователя. |
| MinerU | Инструмент извлечения текста из исходных PDF. |
| GraphRAG | Система, которая извлекает сущности, связи и привязанные фрагменты текста при индексации. |
| Грязный / чистый граф | Два индекса одного корпуса. Для чистого графа текст предварительно очищают, нормализуют и разбивают на части. |
| Чанк / фрагмент источника | Чанк — часть входного текста. Фрагмент источника — единица индекса, связанная с извлечёнными сущностями. |
| Контролируемая прокатка | Обработка стали с управлением температурой и деформацией для получения нужной микроструктуры. |
| Ускоренное охлаждение | Этап быстрого охлаждения. Может проводиться между группами чистовых проходов. |
| Эмбеддинг / вектор признаков | Числовое представление объекта для сравнения или подачи на вход модели. |
| bge-m3 | Многоязычная модель эмбеддингов. Кодирует название и описание вершины в 1024 числа. |
| L2-нормализация | Деление вектора на его евклидову длину. Длина нового вектора равна единице. |
| GNN | Графовая нейронная сеть. Обновляет вектор вершины с учётом её соседей. |
| Передача сообщений | Обмен признаками между соседями и их объединение для обновления представления вершины. |
| GAT | Графовая сеть внимания. Учится определять вклад каждого соседа в представление вершины. |
| Голова внимания | Независимый набор весов соседей и преобразований признаков. |
| GraphSAGE | Архитектура GNN для обработки новых вершин. В этой реализации признаки соседей усредняются. |
| Индуктивное кодирование | Применение обученного кодировщика к новым вершинам или новому графу, например графу запроса. |
| LLM / Qwen2.5-14B | Большая языковая модель. Qwen строит граф запроса, отвечает и проверяет ответы в исходной оценке. |
| RAG | Генерация с поиском. Система сначала находит факты, а затем языковая модель отвечает с их учётом. |
| Поиск / базовый вариант | Поиск ранжирует кандидатов. В базовом варианте сходство вершин определяется косинусом bge-m3. |
| Косинусное сходство | Мера близости направлений двух векторов. Равна их скалярному произведению после L2-нормализации. |
| Гибридная оценка | 0,7 от косинуса bge-m3 плюс 0,3 от среднего косинуса GAT по пяти запускам. |
| Бонус за связь | Надбавка, если связь из запроса соответствует ребру или паре с общим соседом в графе знаний. |
| Стартовая вершина / окрестность | От стартовой вершины строим контекст. В окрестность входят вершины в пределах заданного числа переходов. |
| Промпт / отказ | Промпт содержит вопрос, контекст и инструкцию. При отказе модель сообщает, что сведений для ответа мало. |

## Глоссарий · обучение и оценка

| Термин | Значение в этой работе |
| --- | --- |
| Предсказание связей | Обучение модели присваивать более высокий балл парам, соединённым ребром. |
| Обучение / валидация / тест | На обучении меняем веса, на валидации выбираем состояние модели, на тесте измеряем качество на отложенных рёбрах. |
| Отрицательная пара | Один конец ребра и случайная вершина. Из выборки исключаем пары вершины с собой и известные обучающие рёбра. |
| Утечка данных | Влияние отложенной информации на обучение. При выборе отрицательных пар исключаем только известные обучающие рёбра. |
| Декодер / логит | Декодер превращает два вектора в балл. Здесь логит равен десятикратному косинусному сходству. |
| Бинарная кросс-энтропия | Функция потерь. Штрафует низкие оценки настоящих рёбер и высокие оценки отрицательных пар. |
| ELU / dropout | ELU — нелинейная функция активации. Dropout случайно отключает часть признаков или весов внимания при обучении. |
| Adam / скорость обучения | Adam обновляет веса по статистике градиентов. Скорость обучения задаёт масштаб обновления. |
| Затухание весов | Регуляризация, ограничивающая рост весов модели. |
| Эпоха / ранняя остановка | Эпоха — один шаг обучения по набору обучающих пар. После 30 эпох без улучшения AUC обучение останавливается. |
| Начальное состояние генератора (сид) | Число, задающее начальное состояние генератора случайностей. Для разбиения и обучения берём пять значений. |
| ROC-AUC | Вероятность, что случайное настоящее ребро получит более высокий балл, чем отрицательная пара. При равенстве учитывается половина. |
| Средняя точность (AP) | Сводная оценка точности по мере роста полноты при ранжировании рёбер. |
| Стандартное отклонение | Мера разброса результатов пяти запусков относительно среднего. |
| Релевантная вершина | Вершина, связанная с фрагментом, который соответствует шаблонам фактов для вопроса. |
| MRR / Hit@10 | Средний обратный ранг первой релевантной вершины / доля вопросов с релевантной вершиной в первой десятке. |
| Ключевой факт в контексте | Признак того, что регулярное выражение для эталонного факта нашло совпадение в полном контексте. |
| Эталон / модель-судья | Эталон задаёт ожидаемый факт. Судья сравнивает с ним ответ и присваивает оценку. |
| Доля верных ответов | Число полностью верных ответов, делённое на 26. По этой метрике проверяется порог 60%. |
| Ragas | Библиотека оценки. В работе использованы метрики по ID и смысловые метрики с моделью-судьёй. |
| Эталонный ID | ID фрагмента из заданного источника, в котором совпали все шаблоны фактов для вопроса. |
| Точность по ID | Доля найденных ID фрагментов, которые входят в эталон. |
| Полнота по ID | Доля эталонных ID фрагментов, которые удалось найти. |
| Усреднение по вопросам | Каждый вопрос имеет одинаковый вес при расчёте средней метрики. |
| Процентный пункт | Единица разницы между процентами. Один ответ из 26 соответствует примерно 3,8 процентного пункта. |

**Как читать метрики по ID.** Они измеряют выбор целых фрагментов. Совпадение по шаблону может захватить
лишний текст или пропустить перефразированный факт. Индексы разбивают источники на разные фрагменты. Сравнивайте
способы поиска внутри одного графа.

### Смысловые метрики Ragas · дополнительный слайд 12

**Что сказать.** Полнота контекста (Context Recall) — доля утверждений эталона, которые подтверждает контекст.
Подтверждённость (Faithfulness) — доля подтверждённых утверждений уже в ответе модели. Локальная Qwen2.5-7B-Instruct
оценила все 104 сохранённых случая для базового и гибридного поиска на обоих графах. Судье передавали
восстановленный подграф и исходные фрагменты.

| Граф | Поиск | Полнота контекста (n) | Подтверждённость (n) | Отказы |
| --- | --- | --- | --- | --- |
| Грязный | bge-m3 | 0,481 (26) | 0,778 (15) | 11 |
| Грязный | Гибрид | 0,788 (26) | 0,794 (21) | 5 |
| Чистый | bge-m3 | 0,692 (26) | 0,896 (22) | 4 |
| Чистый | Гибрид | 0,846 (26) | 0,886 (22) | 4 |

**Как читать средние.** Полнота охватывает все 26 вопросов на вариант. Подтверждённость усредняется по
содержательным ответам с оценкой. Явные отказы вынесены в отдельную колонку. Набор содержательных ответов
может различаться между способами поиска. На оценки влияет интерпретация технического материала судьёй.
Для порога 60% используются оценки правильности от Qwen2.5-14B.

[Полнота контекста Ragas](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/context_recall/) и
[Подтверждённость ответа Ragas](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/faithfulness/).
